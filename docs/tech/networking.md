# 네트워크 설계 (Networking)

정본 수치와 게임 규칙은 [design/gdd.md](../design/gdd.md) 17장에 있습니다.
이 문서는 **네트워크 관점의 결정과 경계**만 다룹니다.

## 1. 확정

| 항목 | 결정 | 근거 |
|---|---|---|
| 솔루션 | Photon Fusion 2 | [ADR-0004](../decisions/ADR-0004-photon-fusion-2.md) |
| 토폴로지 | Host Mode (호스트 권위) | ADR-0004 |
| 동시 인원 | 모드 A 8인 | [ADR-0003](../decisions/ADR-0003-낙사형-배틀로얄-승리조건.md) |
| 시뮬레이션 틱 | 60 Hz | gdd 17.1 |
| 캐릭터 이동 | `CharacterController` + 스크립트 속도 관리 | gdd 17.2 |

## 2. 이 게임이 일반 슈터와 다른 점

일반 슈터에서 위치 오차는 보기 불편한 정도지만, **이 게임에서는 위치가 곧 승패**입니다.
낙사선(`Y < -20`)을 넘었는지 아닌지가 처치 판정이므로, 위치 불일치는 곧 판정 불일치입니다.
넉백 동기화는 기능 하나가 아니라 **프로젝트 전체의 성패 조건**입니다 (gdd 21장 최상위 리스크).

## 3. 권위 경계

**호스트 전용** — 클라이언트는 이 계산을 절대 하지 않습니다.

- 폭발 판정: `Physics.OverlapSphere(pos, 4.5f, playerMask)` + 대상별 `Linecast` 벽 관통 차단
- 넉백·견인 속도 결정, HP 감소, 다운 전환, 낙사 판정
- 킬 크레딧(낙사 5초 룰), 축소 페이즈 진행, 매치 상태·순위

**클라이언트** — 표시와 체감 지연 제거만 담당합니다.

- 발사 입력 시 **연출용 가짜 로켓**을 즉시 스폰 (판정 없음)
- HUD, 관전 카메라, 리벤지 연출

담당 스크립트별 실행 위치는 gdd 17.3 표를 따릅니다.

## 4. 넉백 처리 규약

```
물리력(AddForce) 금지 → 결정론적 속도 벡터 대입 → 호스트가 RPC로 브로드캐스트
```

`Rigidbody` + `AddForce`는 클라이언트마다 결과가 미세하게 달라지고, 지연이 겹치면 캐릭터가
순간이동하듯 튑니다. 갈고리 견인도 같은 경로를 씁니다 — 물리력이 아니라 속도 벡터 대입입니다.

**합성 규칙 (D-022 부분 확정)** — 기본값은 `Additive`(합산 후 `maxKnockbackSpeed` 25 m/s로 클램프).
세 모드를 전환 가능하게 구현하고 최종 선택은 M1 플레이테스트 후에 합니다.
상세는 [design/gdd.md](../design/gdd.md) 23.2장.

네트워크 관점에서 걸리는 조건 두 가지:

- 합성은 **호스트에서만** 수행하고, 클라이언트 예측이 **같은 규칙을 재현**할 수 있어야 합니다.
- `Additive`는 같은 프레임에 도착한 폭발의 **적용 순서와 무관하게 같은 결과**를 냅니다(교환법칙).
  `AdditiveDamped`는 순서에 따라 결과가 달라지므로, 이 모드를 최종 채택할 경우
  호스트가 폭발을 정렬하는 기준을 M2에서 따로 정의해야 합니다.

## 5. 남은 결정

| ID | 내용 | 결정 시점 |
|---|---|---|
| D-021 | Fusion 2 라이선스 비용 · 무료 티어 CCU 한도 | **M2 시작 전** |
| D-014 | 모드 B 인원 상한선 (Host Mode 실측) | M2 |
| D-015 | 모드 B 인원수별 초기 반경 스케일링 공식 | M3 |

D-021은 비용 문제라 기술 결정보다 먼저 확인해야 합니다. 한도가 프로젝트 규모에 맞지 않으면
ADR-0004를 대체하는 새 ADR이 필요합니다.

## 6. M2까지 채울 항목

- 동기화 대상 상태 목록과 갱신 빈도
- 넉백 적용 시점의 지연 보상 범위 (얼마나 되감을 것인가)
- 연결 끊김 · 호스트 이탈 처리
- 치팅 대응 경계 (호스트 권위로 어디까지 막히는가)
