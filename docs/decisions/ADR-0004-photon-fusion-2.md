# ADR-0004: 네트워크를 Photon Fusion 2 (Host Mode)로 한다

- 상태: 채택
- 날짜: 2026-09-14
- 결정자: YunPyeongHwa
- 근거 문서: [design/gdd.md](../design/gdd.md) v0.4 — 17.1장, 17.2장, 21장

## 맥락

D-004(네트워크 솔루션)와 D-005(서버 형태)를 정해야 했다.
이 게임에서 가장 어려운 동기화 대상은 **넉백에 의한 강제 이동**이다.
일반 슈터는 위치가 어긋나면 보기 불편한 정도지만, 이 게임은 위치가 곧 승패(낙사)이므로
위치 불일치가 판정 불일치가 된다. [ADR-0003](ADR-0003-낙사형-배틀로얄-승리조건.md) 참조.

## 검토한 선택지

| 선택지 | 장점 | 대가 |
|---|---|---|
| Netcode for GameObjects | Unity 공식, 통합·문서 최상 | 예측·랙 보상을 직접 구현해야 함. 넉백 게임에서 부담이 큼 |
| **Photon Fusion 2 Host Mode (채택)** | 예측·랙 보상 내장. 8인 규모에 적합. 호스트 권위 모델이 명확 | 유료 정책과 CCU 한도. 호스트 이탈 시 매치 중단. 외부 의존성 |
| FishNet | 무료, 예측 기능 성숙 | 커뮤니티 의존. 문제 발생 시 해결 경로가 좁음 |
| 데디케이티드 서버 | 공정성 최상, 치팅 대응 유리 | 운영 비용과 배포 파이프라인 발생. 포트폴리오 범위에 과함 |

## 결정

**Photon Fusion 2를 Host Mode로 쓴다.**

권위 모델:

- 폭발 판정(`OverlapSphere` + 시야 `Linecast`), 넉백 계산, 견인, HP, 다운, 킬 크레딧, 축소 페이즈,
  매치 상태는 **전부 호스트 전용**이다.
- 클라이언트는 발사 시 **연출용 가짜 로켓**을 즉시 스폰해 체감 지연을 없앤다.
  실제 판정은 호스트 로켓이 담당한다.
- 넉백은 물리력이 아니라 **결정론적 속도 벡터**로 처리하고 결과를 RPC로 브로드캐스트한다.
  `Rigidbody` + `AddForce`는 쓰지 않는다.

## 이유

넉백 예측·보정을 직접 구현하는 것이 이 프로젝트의 최대 기술 리스크다.
Fusion 2는 그 부분을 내장하고 있어 리스크를 가장 크게 줄인다.
Host Mode는 데디케이티드의 공정성에는 못 미치지만, 8인 캐주얼 파티 플레이라는 타깃에서는
운영 비용 0의 이점이 더 크다.

## 결과

- **열리는 것**: 예측·랙 보상 내장. 넉백 검증에 집중할 수 있다.
- **닫히는 것**: `Rigidbody` 기반 캐릭터 이동. `CharacterController` + 수동 속도 관리로 간다.
  (`CharacterController`에는 `AddForce`가 없어 수동 관리가 강제되는데, 여기서는 오히려 유리하다)
- **새로 생기는 확인 사항**:
  - D-021 — Fusion 2 라이선스 비용과 무료 티어 CCU 한도. **비용 확인 전에는 M2를 시작하지 않는다.**
  - D-014 — 모드 B "무제한 인원"의 실제 상한. Host Mode 실측 후 결정하며, 전용 서버 전환이
    필요해지면 이 ADR을 대체하는 새 ADR을 쓴다.
- **영향받는 문서**: `tech/networking.md`, `tech/architecture.md`, `rules/code-style.md`
- **되돌리는 비용**: 매우 높음. 네트워크 코드 작성 이후 전환하면 `Network` 레이어 전면 재작성.
  이 때문에 게임플레이 규칙(특히 넉백 계산)은 네트워크 비의존 순수 로직으로 유지한다.
