# ADR-0007: 캐릭터 에셋 반입 규격을 확정한다 (포맷 · 리깅 · 폴리곤 · 텍스처)

- 상태: 채택
- 날짜: 2026-09-16
- 결정자: YunPyeongHwa
- 관련: [ADR-0006](ADR-0006-캐릭터-실루엣-불변.md) (실루엣 불변),
  [ADR-0002](ADR-0002-pc-단독-플랫폼.md) (PC 단독)

## 맥락

3D 모델은 **BARCO AI**로 생성한다. AI 생성 모델은 폴리곤 수·머티리얼 구성·스케일·피벗·본 구조가
매번 다르므로, 규격 없이 반입하면 런타임 성능과 애니메이션이 모두 무너진다.
**첫 캐릭터를 생성하기 전에** 정해야 한다 — 나중에 정하면 만든 모델을 전부 다시 손봐야 한다.

목표 사양은 GTX 1050 / 1080p 60fps이고(gdd 17.1), 모드 A는 8인이 동시에 화면에 들어온다.
후반 난전에서는 캐릭터 8체에 더해 로켓과 폭발 VFX가 초당 수십 개 생성된다(gdd 17.4).

## 결정

| 항목 | 값 |
|---|---|
| 파일 포맷 | **FBX (Binary)** |
| 단위 스케일 | **1 unit = 1 m** |
| 피벗 | **발밑 원점** — 캐릭터가 (0,0,0)에서 +Y로 선다 |
| 정면 축 | **+Z** |
| 폴리곤 예산 | **캐릭터 1체당 8,000 tris 이하** |
| 텍스처 해상도 | **2048 × 2048 상한** |
| 텍스처 채널 | Albedo(필수) · Normal(필수) · MaskMap(선택) |
| 머티리얼 슬롯 | **캐릭터당 1개.** 최대 2개 |
| 리깅 | **Unity Humanoid** |
| 애니메이션 | 모델 파일에 포함하지 않고 별도 관리 |

## 이유

### 리깅 — Humanoid로 통일한다

**이것이 이 ADR에서 가장 되돌리기 어려운 결정이다.**

세 캐릭터는 기본 스펙이 **100% 동일**하다 (gdd 5.1: 체력 100 · 이동 6 m/s · 점프 1.8 m ·
공중 조작력 40%). 차이는 Shift 스킬 하나뿐이다. 즉 걷기·달리기·점프·낙하·넉백 피격·착지 같은
**기본 동작 애니메이션을 셋이 전부 공유한다.**

Humanoid 리깅이면 하나를 만들어 세 캐릭터에 리타게팅할 수 있고, Mixamo 같은 기성 애니메이션도
그대로 쓸 수 있다. Generic으로 가면 캐릭터마다 따로 만들어야 해서 애니메이션 작업량이 3배가 된다.
1인 개발에 AI를 최대한 활용한다는 프로젝트 목표와도 정면으로 어긋난다.

BARCO AI 출력에 리깅이 없거나 비표준이면 리타게팅 후처리를 거친다.

> **주의** — 기즈모의 거대한 오른팔 건틀릿처럼 극단적 비율은 리타게팅 시 어색해질 수 있다.
> 건틀릿은 표준 본에 붙는 **메시**로 처리하고, 본 구조 자체는 좌우 대칭을 유지한다.
> 실루엣의 비대칭([ADR-0006](ADR-0006-캐릭터-실루엣-불변.md))은 메시로 만들지 본으로 만들지 않는다.

### 폴리곤 — 8,000 tris

8체 합계 64,000 tris. GTX 1050에서 VFX와 맵 모듈 분리 연출까지 감당할 여유를 남긴다.

카툰 렌더링(gdd 16장)은 **폴리곤 밀도가 아니라 실루엣과 색이 핵심**이고,
[ADR-0006](ADR-0006-캐릭터-실루엣-불변.md)이 실루엣을 이미 규정했다. 폴리곤을 늘려도
이 게임이 노리는 인상은 좋아지지 않는다. 남는 예산은 폭발 VFX에 쓰는 편이 낫다 —
후반 난전에서 초당 수십 개가 동시에 터진다.

기획서 초안의 15,000 tris도 불가능하진 않지만 LOD 작업을 불러온다. 지금은 LOD 없이 간다.

### 나머지 — Unity 표준을 따른다

FBX·1 m 단위·발밑 피벗·+Z 정면은 Unity에서 다르게 갈 이유가 없다.
glTF는 기본 임포터가 없어 패키지를 추가해야 하고, 얻는 것이 없다.

머티리얼 슬롯을 1개로 묶는 것은 드로우콜 때문이다. 8인 × 슬롯 수만큼 드로우콜이 늘어난다.
카툰 렌더링은 재질 변화가 적어 한 장의 아틀라스로 충분하다.

## 결과

- **열리는 것**: 애니메이션 하나로 세 캐릭터를 움직일 수 있다. 기성 애니메이션 자산을 쓸 수 있다.
- **닫히는 것**: 캐릭터별 고유 골격(4족 보행, 비인간형 등)은 불가능하다.
  현재 캐릭터 3종이 전부 인간형이므로 문제되지 않는다.
- **새로 생기는 작업**: BARCO AI 출력에 리깅이 없으면 리타게팅 후처리 단계가 필요하다.
- **영향받는 문서**: `pipeline/asset-pipeline.md` (반입 절차와 체크리스트)
- **되돌리는 비용**:
  - 리깅 — **높음.** 모델 재리깅 + 애니메이션 에셋 전면 교체
  - 폴리곤·텍스처 — 낮음. 데시메이션과 임포트 설정으로 조정 가능
  - 포맷·스케일·피벗 — 중간. 재내보내기 필요하지만 모델 자체는 살아남는다

## 확인 완료 (2026-09-16)

BARCO AI가 **리깅된 FBX를 출력한다**는 것이 로카(`Rocca.fbx`) 실측으로 확인되었다.
Mixamo 표준 본 22개(필수 15개 전부 포함)에 스키닝과 바인드 포즈까지 들어 있어
**자동 리깅 후처리 단계가 필요 없다.** 텍스처도 2048×2048 PNG 3장이 임베드되어
해상도 규격을 만족한다.

한 가지 주의가 발견되었다 — 텍스처가 `orm.png`(Occlusion·Roughness·Metallic) 형식이라
URP Lit의 MaskMap과 채널 배치가 다르다. 상세와 대응은
[pipeline/asset-pipeline.md](../pipeline/asset-pipeline.md) 2.2절에 기록했다.
