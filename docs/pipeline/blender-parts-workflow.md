# 파츠 반입·보정 공통 워크플로우 (Codex · Blender MCP 실행용)

> **이 문서는 Codex 가 직접 따라 실행하는 절차서입니다.**
> 사용자는 **파츠 모델 파일 경로 하나만** 줍니다. 나머지 판단은 이 문서에 적힌 대로 하십시오.
> 여기에 없는 판단이 필요하면 **멈추고 물으십시오** (10장).

관련 문서 — [ADR-0007](../decisions/ADR-0007-캐릭터-에셋-반입-규격.md) (반입 규격) ·

[asset-pipeline.md](asset-pipeline.md) (전체 파이프라인) ·

## 0. 왜 파츠로 나누는가

**캐릭터 전체를 한 번에 AI 생성하면 품질이 반입 기준에 못 미칩니다.** 2026-09-16 에
VARCO 3D 로 전신 생성을 반복 시도해 확인한 사실입니다. 메시가 뭉치고, 텍스처 UV 가 밀리고,
얇은 돌출물(머리카락·끈·장식)이 덩어리로 복원됩니다.

그래서 **VARCO 3D 에서 파츠별로 생성하고, Blender 에서 보정·조립합니다.**
이 문서는 그 "파츠 하나"에 적용하는 공통 절차입니다.

```
VARCO 3D (파츠 생성)  →  Blender (보정 · 조립 · 리깅)  →  Unity (반입)
                          ↑ 이 문서가 다루는 구간
```

---

## 1. 시작 전에 확정할 것 두 가지

### 1.1 이 파츠는 스킨드인가 강체인가

**이 판단이 이후 절차 전체를 가릅니다.** 먼저 정하고 시작하십시오.

| 분류 | 해당 파츠 | 특징 | 절차 |
|---|---|---|---|
| **스킨드** | 베이스 바디(얼굴·맨손·언더수트) · 의상(아머·부츠) | 몸을 따라 굽는다. 스켈레톤에 바인딩 | 5.1 리토폴로지 **필수** |
| **강체** | 헤어 · 고글 · 추진기 포드 · 건틀릿 · 무기 | 굽지 않는다. 본에 부착 | 5.1 **생략**, 부착점만 정리 |

판단 기준은 하나입니다 — **캐릭터가 걸을 때 이 파츠가 휘어야 하는가.**
휘어야 하면 스킨드, 아니면 강체입니다.

> 옷 조각만 따로 `Rig` 노드에 넣으면 스켈레톤이 심어지지 않습니다.
> 스킨드 파츠는 **베이스 바디의 아마추어에 `Automatic Weights` 로 바인딩**합니다.
> 상세는 [ADR-0008](../decisions/ADR-0008-모듈러-캐릭터-구조.md).

### 1.2 목표 규격 (ADR-0007)

| 항목 | 값 |
|---|---|
| 포맷 | FBX (Binary) |
| 스케일 | 1 unit = 1 m |
| 피벗 | 발밑 원점 (파츠도 조립 기준 원점에 맞춘다) |
| 정면 축 | +Z |
| 폴리곤 | **캐릭터 1체 합계 15,000 tris 이하** — 파츠 예산은 조립 전에 배분한다 |
| 텍스처 | 2048 × 2048 상한 |
| 리깅 | Unity Humanoid (베이스 바디 기준) |

## 2. 작업 폴더를 먼저 만든다

**메시를 건드리기 전에 폴더부터 만드십시오.** 반복 작업이 서너 단계만 넘어가도
어느 파일이 최신인지 분간이 안 됩니다.

```
3D_Model/<Character>/
├── 00_OriginalModels/
│   └── <Part>/                  ← 원본. 절대 덮어쓰지 않는다
│       ├── model.usda
│       ├── *_base_color.png / *_normal.png / *_orm.png
│       └── <Part>_Recovered.blend
├── 01_<Stage>/
│   ├── <Character>_<Part>_<Stage>_<YYYYMMDD_HHMMSS>.blend
│   ├── (해당 단계의 텍스처 · 참고 이미지 · 백업)
│   └── 8방향확인/
│       └── <YYYYMMDD_HHMMSS>/   ← 검수 시점별로 묶는다
├── 02_<Stage>/
└── ...
```

규칙 네 개입니다.

1. **한 폴더 = Blender 파일 한 개 + 관련 파일.** 한 폴더에 단계를 섞지 않습니다.
2. **수정본 파일명에 `_YYYYMMDD_HHMMSS`** 를 붙입니다. 진행 순서가 파일명만으로 보여야 합니다.
3. **8방향 확인 이미지는 `8방향확인/<날짜_시간>/`** 에 시점별로 묶습니다. 비교가 가능해야 합니다.
4. **`00_OriginalModels/` 는 읽기 전용으로 취급합니다.** AI 생성물은 같은 것을 다시 받을 수
   없습니다. 덮어쓰면 복구 수단이 없습니다.

폴더 구성을 바꿨으면 `README_<YYYYMMDD_HHMMSS>.md` 에 구성을 적어 남기십시오.

## 3. 반입 직후 점검

### 3.1 확장자

VARCO 3D 는 **`.usda`** 로 내보냅니다. `.usd` · `.usda` · `.usdc` 를 모두 확인하십시오.
브리지가 `.usdc` 만 찾아 실패하던 문제가 있었고 2026-09-17 에 수정했습니다.
같은 증상이 다시 보이면 브리지 쪽 확장자 처리를 먼저 의심하십시오.

> **같은 시간에 뜬 오류가 같은 원인이라고 보지 마십시오.** 위 확장자 문제와 무관하게
> "다운로드 폴더에 없는 파일을 열려다 난 오류"가 겹쳐 뜬 사례가 있었습니다.

### 3.2 기록할 것

원본을 수정하기 전에 상태를 먼저 기록하십시오. 보고에 그대로 씁니다.

- 정점 수 · 삼각형 수
- 텍스처 매수와 채널 (base_color / normal / orm)
- UV 유무
- **아마추어(Armature) 유무** — VARCO 출력은 없는 경우가 많다
- 스케일 · 피벗 위치 · 정면 축

### 3.3 원본 보존

점검이 끝나면 **원본 상태 그대로** `00_OriginalModels/<Part>/` 에 저장합니다.
이 시점에는 어떤 수정도 하지 않습니다.

## 4. 단계마다 저장한다

**각 단계를 끝낼 때마다 저장하고 다음으로 넘어가십시오.**

저장하지 않은 채 수정을 쌓다가 외부 서비스 오류로 후속 작업이 통째로 막힌 적이 있습니다
(`Selected model is at capacity`). 그때 살아남은 것은 "Blender 를 닫지 마십시오"뿐이었습니다.
같은 상황을 만들지 마십시오.

## 5. 메시 보정

### 5.1 리토폴로지 — 스킨드 파츠만

용도는 **Unity 게임 애니메이션**입니다. 단순 폴리곤 감소가 아니라
**관절이 자연스럽게 구부러지도록 면 흐름을 다시 구성**하는 작업입니다.

| 항목 | 기준 |
|---|---|
| 폴리곤 | 파츠에 배분된 예산 이하 (참고: 로카 전신 15,000 → 11,562) |
| 관절 루프 | 어깨 · 팔꿈치 · 무릎에 루프 추가. 손가락이 있으면 손가락도 |
| UV | 새로 펴고 2K 로 베이크 |
| 검사 | 구멍 없음 · 면적 0 인 면 없음 · **FBX 재가져오기 통과** |
| 원본 | 보존 (2장) |

### 5.2 AI 생성물 상습 결함 점검표

VARCO 출력에서 반복적으로 나오는 것들입니다. **지적받기 전에 먼저 확인하십시오.**

| 부위 | 증상 | 대응 |
|---|---|---|
| 얼굴 | 광대 · 눈 주변 · 코 · 입의 곡면이 뭉개짐 | 곡면 보정 |
| 손 | 손가락이 뭉쳐 덩어리가 됨 | **다섯 손가락 메시로 교체** |
| 신발 | 끈과 끈 구멍이 뭉개짐 | 재구성 |
| 겨드랑이 · 옆구리 | 팔과 몸통 사이가 물갈퀴처럼 메워짐 | 생성 단계에서 `tPose=1` 미적용이 원인. 심하면 재생성을 건의 |
| 머리카락 · 얇은 장식 | 덩어리로 뭉침 | 단일 정면 이미지의 구조적 한계. **별도 파츠로 분리 생성**을 건의 |

### 5.3 하지 말 것

- **폴리곤 수를 올려 형태를 고치려 하지 마십시오.** 폴리곤은 형태 정확도가 아니라
  표현 상한입니다. 모델이 머리카락을 평면으로 이해하면 폴리곤을 10 배 줘도 평면이
  10 배 촘촘해질 뿐입니다.
- **`Ctrl+J` 로 합치고 끝내지 마십시오.** 오브젝트를 묶는 기능일 뿐,
  **겹친 면을 정리하거나 경계의 정점을 이어주지 않습니다.**
- **실루엣을 바꾸지 마십시오.** 실루엣은 스킨 불변 요소입니다
  ([ADR-0006](../decisions/ADR-0006-캐릭터-실루엣-불변.md)). 바꿔야 할 것 같으면 멈추고 물으십시오.

## 6. 텍스처

### 6.1 음영 — 무엇을 굽고 무엇을 굽지 않는가

**이 경계를 잘못 잡으면 두 번 일합니다.** 한쪽으로 몰면 실패합니다.

| | 내용 | 이유 |
|---|---|---|
| **굽는다** | 가는 머릿결 음영, 천 결, 미세 홈 — **메시에 없는 형태 정보** | 메시가 표현하지 못하는 디테일을 텍스처가 대신한다 |
| **굽지 않는다** | 넓게 깔린 어두운 그림자, 전체적인 명암 | **Unity 가 조명으로 계산한다.** 미리 구우면 이중으로 어두워진다 |

> 실제로 "그림자를 텍스처에 넣지 말라"를 그대로 적용했다가 **머릿결 음영까지 사라져**
> 단색 덩어리가 된 적이 있습니다. 원칙은 맞지만 적용 범위가 과했던 것입니다.

### 6.2 색이 죽어 보일 때

참고 이미지는 색이 진한데 Blender 모델은 탁하게 나오는 경우,
**텍스처를 더 진하게 칠하지 마십시오.** 먼저 다음을 확인합니다.

1. 색상 관리(Color Management) 설정
2. 노출(Exposure)
3. 반사광 / 셰이더 설정

텍스처를 진하게 만들어 맞추면 조명이 바뀔 때 다시 틀어집니다.

### 6.3 해상도

2048 × 2048 상한입니다 (ADR-0007). 4K 로 작업했으면 반입 전에 2K 로 내립니다.

## 7. 8방향 검수 — 마무리 기준

**정면만 보고 끝내지 마십시오.** 다음 8방향을 전수 확인합니다.

```
좌 · 우 · 앞 · 뒤 · 위 · 아래 · 앞대각 · 뒤대각
```

- 이미지는 `8방향확인/<YYYYMMDD_HHMMSS>/` 에 저장합니다.
- 문제를 찾으면 보정하고 **다시 8방향을 찍어 재검사**합니다.
- **8방향 검수를 통과하기 전에는 완료로 보고하지 마십시오.**

자주 걸리는 것 — 위쪽 얼룩, 아래쪽 결 끊김, 측면 이음새, 색 경계선.
정면에서는 어느 것도 보이지 않습니다.

이 검수는 [asset-pipeline 4.7](asset-pipeline.md) 의 **실루엣 테스트와 별개**입니다.
실루엣 테스트는 조립이 끝난 캐릭터 단위로 합니다.

## 8. 내보내기

1. FBX (Binary) 로 내보냅니다.
2. 1.2 의 규격을 항목별로 다시 대조합니다.
3. 명명 규칙은 [asset-pipeline 3장](asset-pipeline.md) 을 따릅니다.
   VARCO 출력 파일명(`Rocca.fbx`)을 그대로 두지 마십시오.
4. Unity 반입 위치는 `Assets/_Project/Art/Characters/<Character>/` 입니다.

## 9. 보고 형식

작업이 끝나면 아래 형식으로 보고하십시오. **추측으로 채우지 말고 실제 수치를 넣으십시오.**

```
## 파츠 작업 보고 — <Character> / <Part>

- 분류: 스킨드 | 강체
- 반입 시 상태: 정점 N · 삼각형 N · 텍스처 N장 · 아마추어 유/무
- 작업 후: 삼각형 N (변화량)
- 수정한 것: (항목별)
- 8방향 검수: 통과 | 미통과 — 발견한 문제와 보정 내역
- 남은 문제: (있으면 그대로. 없으면 "없음")
- 저장 위치: <폴더> / <파일명>
- 아키텍트 확인 필요: (없으면 "없음")
```

## 10. 멈추고 물어야 하는 경우

아래에 해당하면 **임의로 진행하지 말고 보고한 뒤 답을 기다리십시오.**

| 상황 | 이유 |
|---|---|
| 스킨드/강체 판단이 서지 않는다 | 이후 절차 전체가 갈린다 |
| **실루엣이 바뀌는 수정이 필요해 보인다** | ADR-0006 위반. 설계 변경 권한은 아키텍트에게 있다 |
| 폴리곤 예산을 지킬 수 없다 | 규격(ADR-0007)을 건드리는 결정이다 |
| 원본 품질이 보정으로 못 살릴 수준이다 | 재생성이 싸다. VARCO 3D 재생성은 200 크레딧, 이미지 재생성은 20 크레딧 |
| 외부 서비스 오류로 막혔다 | 기다리는 것 외에 방법이 없다. **중간 산출물을 먼저 저장하고** 보고한다 |
