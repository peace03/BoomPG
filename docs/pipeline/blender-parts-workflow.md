# 원화 기준 파츠 보정 워크플로우 (Codex · Blender MCP 실행용)

> **원화를 목표로 삼고, VARCO AI 생성 GLB를 작업 시작점으로 사용합니다.**
> 원화 요소를 분석표에 기록한 뒤 메시와 텍스처를 수정합니다.
> **수정 → 8방향 확인 → 보정**을 반복하고, 원화 요소를 충족했을 때 보고하고 종료합니다.
> 파일이 열리거나 검수 이미지 8장이 생성된 것만으로 완료 처리하지 않습니다.

## 0. 실행 순서

```text
원화 분석 + 파츠별 원본 보존
    ↓
VARCO AI GLB 반입 점검
    ↓
분석표에 따라 메시 및 텍스처 수정 → 수정본 저장
    ↓
8방향 전체 확인 + 원화와 비교
    ├─ 미충족 요소 있음 → 원인 기록 → 보정 → 새로운 8방향 전체 확인 ↺
    └─ 원화 요소 충족 + 기술 검증 통과 → 최종 저장·내보내기 → 보고·종료
```

폴더 정리만 요청받은 작업에서는 경로와 파일 무결성을 검증합니다. 과거 검수 결과를
새 분석표로 재검수한 결과처럼 바꾸거나, 정리하면서 임의로 모델을 보정하지 않습니다.

## 1. 캐릭터 → 파츠 → 원본·수정본 구조

작업 전에 해당 파츠 폴더를 만들고 원본과 수정본을 분리합니다.

```text
3D_Model/<Character>/
├── README_<YYYYMMDD_HHMMSS>.md       # 파츠별 최신 작업본 링크
├── Hair/                           # 파츠 1
│   ├── 00_Original/                # 수정하지 않은 원본 모듈
│   │   ├── <Character>_Hair_Original.blend
│   │   ├── <원본 파일명>.glb
│   │   └── <원화·원본 텍스처·관련 파일>
│   ├── 01_Revision_<Stage>/        # 수정본 1
│   │   ├── <Character>_Hair_<Stage>_<YYYYMMDD_HHMMSS>.blend
│   │   ├── Textures/              # 이 수정본이 실제 사용하는 이미지
│   │   ├── Sources/               # 참고 원화·베이크 입력 등
│   │   ├── Notes/                 # 분석표·변경 내역·검증 결과
│   │   ├── Exports/               # 이 수정본에서 내보낸 FBX 등
│   │   ├── Backups/               # 자동 백업·압축 보관본
│   │   └── 8방향확인/
│   │       ├── <YYYYMMDD_HHMMSS>/  # 첫 검수
│   │       └── <YYYYMMDD_HHMMSS>/  # 보정 후 재검수
│   └── 02_Revision_<Stage>/        # 수정본 2, 동일한 내부 구조
├── Goggles/                        # 파츠 2, 동일한 내부 구조
├── Clothing/                       # 옷, 실제 작업을 시작할 때 생성
└── Body/                           # 몸체, 실제 작업을 시작할 때 생성
```

- **원본·수정본 폴더 하나당 활성 `.blend` 한 개와 관련 파일**을 둡니다. 다른 파츠의 단계를 섞지 않습니다.
- 수정본 번호는 **파츠별로** 증가시킵니다. 새로 생성·수정한 산출물에는 `_YYYYMMDD_HHMMSS`를 붙입니다. 시간 기준은 한국 시간입니다.
- `00_Original`의 GLB·원화·텍스처와 최초 반입 상태의 Blender 파일은 덮어쓰지 않습니다.
  기존 USD 계열 원본은 그대로 보존하며, GLB 원본이었던 것처럼 변환·대체하지 않습니다.
- 수정본마다 사용 텍스처를 함께 두고 Blender에는 상대 경로로 연결합니다. 필요한 이미지는 패킹합니다.
  패킹 내부 경로도 확인합니다. 다른 수정본이나 임시 폴더의 파일에 의존하지 않습니다.
- 자동 `.blend1`과 과거 Blender 백업은 `Backups/`에 보관합니다. 실패한 시험본도 삭제하지 않고 상태를 표시합니다.
- 검수 폴더에는 8장, 비교용 이미지, 검수 기록을 같은 시점으로 묶습니다. 보정 전 이미지를 덮어쓰지 않습니다.
- 구조를 옮길 때는 이동 전후 경로와 원본 해시를 기록하고, 모든 Blender 파일을 다시 열어 이미지·링크를 확인합니다.
  과거 보고서의 측정값·검수 판정은 보존하고, 현재 경로 안내는 새 날짜의 README에 씁니다.

## 2. 원화 분석 — 수정 전에 합격 기준을 만든다

### 2.1 근거와 불확실성

1. 사용자 원화와 추가 지시를 확인하고 원화 파일을 `Sources/`에 보관합니다.
2. 아래 분석 항목을 파츠에 적용합니다. 구조나 재질이 불명확하면 공식 제작 자료·실물 제조사 자료 등을
   인터넷에서 추가 조사하고, 사용한 URL과 확인 날짜를 분석 기록에 남깁니다.
3. 인터넷 자료는 구조를 이해하는 보조 근거입니다. 원화의 스타일·과장·비대칭을 실물 비율로 임의 교정하지 않습니다.
4. **관찰 사실 / 추정 / 사용자 확정**을 구분합니다. 단일 원근 이미지로 정확한 실제 크기나 가려진 뒷면을 확정하지 않습니다.
5. 실제 치수가 없으면 전체 폭 등을 기준으로 비율을 기록합니다. 작업용 임시 치수와 최종 조립 치수를 구분합니다.
   사용자가 이미 정한 치수나 허용한 재구성은 다시 승인받지 않습니다.

아래 표는 11장의 공식 자료와 이 프로젝트의 작업 요구를 종합한 점검표입니다.
모든 파츠에 같은 치수나 허용 오차를 강제하는 표준은 아닙니다.

### 2.2 분석 항목

| 요소 | 원화에서 분석할 내용 | 모델에서 확인할 내용 |
|---|---|---|
| 컨셉·정체성 | 캐릭터 성격, 파츠 기능, 스타일, 강조점, 핵심 색과 형태 | 작은 화면에서도 핵심 특징이 읽히는지, 다른 디자인으로 바뀌지 않았는지 |
| 실루엣·큰 덩어리 | 외곽선, 돌출부, 볼륨 분포, 둥글거나 각진 정도 | 정면·측면·후면 외곽, 곡률, 덩어리 간 비율 |
| 전체 크기·비율 | 폭·높이·깊이 비율, 머리·몸과의 상대 크기 | 단위와 실제 치수, 좌우 폭, 상하 높이, 앞뒤 길이를 각각 측정 |
| 국소 높이·폭 | 렌즈 높이, 프레임 테두리 폭, 밴드 폭, 손가락 굵기 등 | 전체 바운딩 박스에 가려진 부분별 치수와 비율 |
| 두께·단면 | 재료 자체 두께, 속이 찬 부분/빈 부분, 단면 모양 | 앞·뒤 표면 간 거리, 얇은 끝의 소실, 실제 단면의 부피감 |
| 깊이·단차 | 렌즈가 들어간 정도, 돌출·함몰, 층간 높이 차, 모서리 라운딩 | 프레임 전후 깊이, 렌즈와 프레임 단차, 베벨 폭과 곡면 연결 |
| 빈 공간·결합부 | 코 파임, 고리 내부, 관통 구멍, 부품 겹침 순서, 연결 방식 | 막힌 구멍, 잘못 메워진 공간, 떠 있는 부품, 틈·간섭·관통 |
| 대칭·배치 | 의도된 좌우 대칭/비대칭, 부품 수, 각도, 간격 | 중심선, 랜드마크 위치, 부품 누락·중복·잘못된 반복 |
| 중간 형태 | 머리 가닥 묶음, 천 주름, 프레임 굴곡, 장갑·부츠 구조 | 큰 형태를 유지한 상태에서 주름·가닥·패널 흐름 재현 |
| 미세 디테일 | 머릿결 방향, 재봉선, 끈, 홈, 직물 결, 로고, 마모 | 게임 화면 크기에서 읽히는지, 메시/Normal/색 중 적절한 채널에 있는지 |
| 색·패턴 | 주색·보조색·강조색, 면적 비율, 경계, 앞뒤 연속성 | 원화의 색 관계, UV 경계의 끊김·번짐·늘어짐, 뒤쪽 패턴 누락 |
| 재질·표면 | 금속/플라스틱/천/유리 등의 구분, 거칠기, 반사, 투명도 | Base Color·Metallic·Roughness·Normal·Opacity의 역할, 렌즈 재질의 입체감 |
| 조명·카메라 영향 | 원근, 시점, 가림, 광원 방향, 하이라이트, 그림자, 배경색 | 형태/고유색 차이와 조명/노출 차이를 구분, 비교 카메라 맞추기 |
| 해부학·변형 | 얼굴 랜드마크, 눈꺼풀·입술, 손가락 수, 관절과 옷의 당김 | 부자연스러운 광대·눈·손, 관절 면 흐름, 변형 시 찌그러짐 |
| 조립·게임 조건 | 부착 위치, 움직이는 부분, 인접 파츠, 게임 카메라 거리 | 간섭 여유, 본/웨이트, 파츠 예산, UV 해상도, 최종 축·피벗 |
| 보이지 않는 부분 | 원화로 알 수 없는 뒤·안쪽·바닥 구조 | 보이는 구조와 일관된 보완, 추정 근거 기록, 중요한 미확정 사항 분리 |

**고글 예시:** `렌즈의 세로 높이`, `프레임 테두리 폭`, `프레임 앞뒤 깊이`,
`프레임 대비 렌즈 함몰 깊이`, `유리 자체 두께`는 서로 다른 항목입니다.
전체 크기 하나를 키웠다고 모두 충족한 것으로 판정하지 않습니다.
현재 Spark 고글의 폭 20 cm는 사용자 확정값이며 다른 파츠의 기본값이 아닙니다.

### 2.3 분석 기록과 판정

`Notes/Analysis_<YYYYMMDD_HHMMSS>.md`에 아래 형식으로 기록합니다.
각 적용 항목에 ID를 부여하고 수정·검수 내역에서도 같은 ID를 사용합니다.

| ID | 요소·우선순위 | 원화 근거·관찰/추정/확정 | 목표 치수·비율 또는 시각 기준 | 현재 상태 | 확인 방향·증거 | 판정 |
|---|---|---|---|---|---|---|
| G01 | 렌즈 높이 · 필수 | 원화 외곽과 코 파임 | 전체 폭 대비 높이, 측정 지점 표시 | 실측값/차이 | 앞·앞대각·원화 비교 | 미충족 |
| G02 | 프레임 깊이 · 필수 | 원화 측면과 사용자 지시 | 전후 면 사이 두께감, 단면 기준 | 실측값/차이 | 좌·우·위·아래·뒤대각 | 미충족 |

- 기준은 수정 전에 기록합니다. 치수가 있으면 측정 지점·단위·허용 오차도 적습니다.
  수치가 없는 스타일 요소에는 확인 가능한 특징과 비교 이미지를 사용합니다.
- 판정은 `충족 / 미충족 / 미확인 / 해당 없음`으로 표시합니다. 해당 없음에는 이유를 적습니다.
- 원화의 핵심 형태·색·디테일은 필수입니다. 구현이 어렵다는 이유로 선택 항목이나 해당 없음으로 낮추지 않습니다.
- 원화에 없는 추가 장식은 선택 사항입니다. 뒷면처럼 추정이 필요한 부분은 추정임을 기록하고
  일관성을 검수합니다. 원화에서 직접 확인한 사실처럼 보고하지 않습니다.

## 3. VARCO AI GLB 반입 점검과 원본 저장

1. 원본 `.glb`, 원화, 제공된 부속 파일을 `00_Original/`에 보존하고 해시를 기록합니다.
2. GLB를 Blender에 가져와 **수정 전 상태**의 Blender 파일을 원본 폴더에 한 개 저장합니다.
   이미지가 내장되어 있으면 패킹 여부와 외부 저장 경로를 확인합니다.
3. 다음을 `Notes/Intake_<YYYYMMDD_HHMMSS>.md` 또는 JSON에 기록합니다.
   - 정점·삼각형·오브젝트·머티리얼 수, UV 레이어와 겹침/왜곡 여부
   - 텍스처 해상도·채널·색 공간·누락, GLB 내장 이미지 유무
   - Armature·웨이트·애니메이션 유무
   - 폭·높이·깊이, 단위, 원점·변환·정면 축
   - 뭉친 부품, 구멍, 뒤집힌 면, 중복·퇴화 면 등 초기 결함
4. 작업용 수정본을 별도 폴더에 저장하고 분석표와 대조합니다.

기존 `.usd/.usda/.usdc/.usdz` 자산은 실제 파일 내용을 확인해 반입합니다.
확장자 탐색 오류와 존재하지 않는 `.blend`를 여는 오류를 구분합니다.
VARCO가 항상 한 확장자로만 내보낸다고 가정하지 않습니다.

## 4. 메시 수정 — 큰 형태부터 원화에 맞춘다

### 4.1 작업 순서

1. **전체 실루엣·비율·큰 볼륨**을 맞춥니다.
2. **부분 높이·폭·깊이·재료 두께·단차·빈 공간**을 분석표대로 보정합니다.
   필요하면 단면과 Blender Measure 도구로 측정합니다. 전체 Dimensions로 국소 두께를 대신하지 않습니다.
3. 뭉친 프레임·렌즈·밴드, 손가락, 신발 끈 등은 필요한 부분을 재구성합니다.
   원화에 맞추는 보정과 이미 허용된 재구성은 승인 범위 안에서 진행합니다.
4. 중간 형태·미세 디테일을 추가합니다. 실루엣에 영향을 주는 형태는 메시로,
   작은 표면 정보는 Normal 또는 텍스처로 표현합니다.
5. 면 방향, 중복·퇴화 면, 의도하지 않은 구멍·교차, 셰이딩을 확인한 뒤 UV를 정리합니다.
   의도된 열린 면은 이유를 기록합니다. 모든 파츠를 무조건 폐곡면으로 만들지는 않습니다.

폴리곤 증가나 전체 Smooth만으로 뭉친 형태를 해결했다고 판단하지 않습니다.
`Ctrl+J`는 오브젝트 결합일 뿐 경계 연결·겹친 면 제거가 아니므로 필요한 메시 정리를 따로 합니다.
겨드랑이가 붙는 등 AI 생성 결함의 원인은 실제 파일·생성 설정을 확인해 판단합니다.

### 4.2 움직임에 따른 보정

| 분류 | 적용 | 검증 |
|---|---|---|
| 스킨드 | 베이스 바디·의상처럼 몸을 따라 휘는 파츠 | 관절과 얼굴 표정에 필요한 면 흐름, 손가락 분리, 웨이트와 대표 포즈 변형 |
| 강체 | ADR-0008의 헤어·고글·장비처럼 본에 부착하는 파츠 | 실루엣·면 품질·폴리곤 예산·부착점·간섭; 불필요한 리깅은 추가하지 않음 |

스킨드 파츠는 단순 Decimate를 애니메이션용 리토폴로지로 보고하지 않습니다.
의상은 베이스 바디의 아마추어에 바인딩하고 자동 웨이트 결과를 확인·보정합니다.
몸체가 아직 없으면 바인딩·조립 검증은 미실시로 명시합니다.

## 5. 텍스처 수정 — 원화의 색과 재질을 분리해 재현

- 큰 형태 수정 후 UV를 정리하고, 기존 텍스처를 재투영하거나 베이크·수정합니다.
  늘어짐, 이음새, 섬 간 여백, 파츠 간 텍셀 밀도(표면 면적당 픽셀 수)를 확인합니다.
- 원화의 주색·강조색·패턴 위치를 맞추고 뒤쪽과 안쪽까지 연속성을 확인합니다.
- **가는 머릿결 음영·미세 홈·직물 결은 유지합니다.** 전체에 깔린 큰 그림자,
  방향성 광원·강한 반사 하이라이트는 Base Color에 고정하지 않습니다.
  재질에 의한 반사와 큰 그림자는 Unity의 조명·셰이더가 계산하도록 분리합니다.
- Base Color의 고유색과 Roughness·Metallic·Normal의 표면 정보를 구분합니다.
  검은 렌즈라고 금속이나 투명 유리로 단정하지 않고 원화의 외관과 용도를 기준으로 정합니다.
- 색이 탁하면 색 공간, Color Management, 노출, 조명, 셰이더를 먼저 확인한 뒤 실제 색을 수정합니다.
  원화와 맞아 보이도록 과한 채도나 발광을 임시로 넣어 문제를 가리지 않습니다.
- 색상 이미지와 데이터 맵의 색 공간을 구분합니다. 엔진의 실제 셰이더에 맞게 채널을 연결합니다.
  VARCO ORM을 Unity용 맵과 같은 채널 배치라고 가정하지 않습니다.
- 최종 이미지 해상도는 2048 × 2048 이하입니다. 수정본의 텍스처 경로와 패킹을 확인하고 저장합니다.

## 6. 반복 검수 — 수정 → 8방향 확인 → 보정

### 6.1 매 회차의 증거

검수할 수정본을 저장한 다음, **같은 메시·텍스처 상태에서** 아래 8방향을 모두 생성합니다.

```text
좌 · 우 · 앞 · 뒤 · 위 · 아래 · 앞대각 · 뒤대각
```

- `8방향확인/<YYYYMMDD_HHMMSS>/`에 방향이 드러나는 파일명으로 저장합니다.
- 파츠의 정면 축을 먼저 정합니다. 카메라 위치·대각선 방향·투영 방식·크기·해상도·조명·색상 관리 값을
  기록하고 회차 사이에 유지합니다. 설정을 바꾸면 비교 조건이 달라졌다고 표시합니다.
- 기본 형태 비교에는 직교 뷰를 사용합니다. **원근 원화와 비교할 때는 원화 시점에 맞춘 원근 뷰를 추가**합니다.
  카메라 차이를 메시 비율 오류로 오인하지 않습니다.
- 주요 두께·결합부가 작게 보이면 확대 또는 단면 이미지를 추가합니다.
  색은 조명을 배제한 Base Color 확인과 재질·조명 포함 확인을 나눠 점검합니다.
- 8방향을 나란히 볼 수 있는 목록 또는 연락판과 검수 기록을 남깁니다.

### 6.2 반드시 이미지를 열어 확인할 것

| 확인 대상 | 주요 발견 지점 |
|---|---|
| 원화 분석표의 모든 적용 요소 | 원화와 대응하는 시점, 부분 확대, 측정값 |
| 볼륨·국소 두께·단차 | 좌·우·위·아래·대각선; 정면만으로 통과시키지 않음 |
| 빈 공간·안쪽·결합부 | 뒤·아래·뒤대각; 막힘, 관통, 떠 있는 틈 |
| 색·결·패턴·재질 | 전체 8방향; 얼룩, 결 끊김, 뒷면 누락, 이음새, 색 경계 |
| 면·셰이딩 | 전체 8방향; 꺾임, 핀칭, 역면, 반사 왜곡 |

8장의 존재 여부를 자동 확인하는 것과 시각 검수는 별개입니다.
이미지를 실제로 열어 확인하고, 각 방향의 결과와 문제 위치를 기록합니다.

### 6.3 미충족이면 다음 회차로

1. 미충족 ID, 관찰된 차이, 원인, 다음 수정 내용을 기록합니다.
2. **실루엣·비율·두께 → 결합·중간 형태 → 재질·색 → 미세 디테일** 순서로 보정합니다.
3. 새 수정본 또는 새 날짜의 산출물을 저장하고 **8방향 전체를 다시 확인**합니다.
   수정한 부분의 확대 사진 하나로 이전 전체 검수를 대체하지 않습니다.
4. 이전 회차와 비교해 개선 여부와 새로 생긴 문제를 확인하고 분석표 판정을 갱신합니다.

정해진 횟수만 반복하고 끝내거나, 어려운 요소를 누락한 채 완료로 보고하지 않습니다.
진행 불가 사유가 생기면 중간본을 저장하고 미충족 항목과 필요한 결정을 보고합니다(10장).

## 10. 진행 중 확인이 필요한 경우

- 원화나 추가 치수가 없어 **핵심 형태를 결정할 수 없을 때**, 필요한 정보만 묻고 독립적인 점검을 계속합니다.
- 원화 재현을 넘어 캐릭터 컨셉·의도된 실루엣·파츠 구성을 새로 바꾸거나 프로젝트 예산을 초과해야 하면 확인합니다.
  원화에 맞추는 통상 보정과 이미 사용자가 허용한 실루엣 재구성은 재확인하지 않습니다.
- 새 유료 생성 등 현재 승인 범위를 벗어난 작업은 비용·대안을 확인합니다. 과거 서비스 가격을 현재 가격으로 단정하지 않습니다.
- 도구·서비스 오류가 나면 가능한 중간 산출물을 먼저 저장하고 허용된 대체 방법으로 진행합니다.
  남은 필수 검증이 불가능하면 이유·미완료 항목을 보고합니다. 오류를 통과로 바꾸지 않습니다.
