# 07. FBX 내보내기·Unity 반입·보고

[메인 목차](../blender-parts-workflow.md) · 이전: [06. 검수](06-review.md)

## 목적과 입력

검수한 외관과 데이터가 저장·반입 과정에서도 유지되는지 확인하고, 완료한 범위를 정확히 전달한다.
입력은 06을 통과한 저장본, 원화 판정표, 최신 8방향 증거, 내보내기 대상·축·실제 크기·피벗 결정이다.
파일 흐름 중 **Blender(`.blend`) → FBX + 텍스처 → Unity** 구간을 수행한다.

**파츠의 원화 재현 완료와 리깅·조립·Unity 동작 완료는 별도 상태다.**
리그나 캐릭터가 없어 못 한 검증, 조립 때 정하기로 한 위치는 후속 항목으로 기록한다.
적용되는 필수 원화 항목이나 파츠 기술 검증이 남았으면 최종 완료로 표시하지 않는다.
Unity까지 포함한 전체 흐름은 실제 반입·검증 후 완료한다. 요청 범위가 중간 단계까지라면
`Blender 보정 완료` 또는 `FBX 전달 준비 완료`와 `Unity 반입·검증 미실시`를 구별해 보고한다.

## 쉬운 용어

| 용어 | 뜻 |
|---|---|
| 피벗 | 회전·이동 기준점. 완성 캐릭터의 발바닥 기준과 단독 장비의 부착 기준은 구별 |
| 패킹·상대 경로 | 이미지를 Blender 파일 안에 포함 / 현재 파일을 기준으로 외부 파일 위치를 연결 |
| 재반입 | 내보낸 파일을 별도 장면에 다시 가져와 실제 결과를 검사하는 것 |
| GUID·`.meta` | Unity가 파일을 추적하는 식별자와 그 정보 파일. 교체 시 연결 유지에 중요 |

## 프로젝트 규격

근거는 [ADR-0007](../../decisions/ADR-0007-캐릭터-에셋-반입-규격.md),
이를 개정한 [ADR-0008의 최신 결정](../../decisions/ADR-0008-모듈러-캐릭터-구조.md),
[asset-pipeline의 최종본 관리](../asset-pipeline.md)다. 임의의 새로운 파츠 예산을 만들지 않는다.

| 항목 | 기준 |
|---|---|
| 게임용 포맷 | FBX Binary |
| 단위·축 | Unity 기준 1 unit = 1 m, Y-Up, Z-Forward. 실제 반입 결과로 확인 |
| 피벗 | 완성 캐릭터는 발바닥 중심. 단독 파츠는 합의한 부착 기준 또는 조립 시 확정 상태 기록 |
| 삼각형 수 | 캐릭터 모든 파츠 합계 15,000 tris 이내. 개별 배분·현재 합계를 별도 기록 |
| 머티리얼 | 파츠당 1개, 캐릭터 합계 최대 7개 |
| 텍스처 | 최대 2048×2048. Albedo·Normal 및 실제 셰이더가 사용하는 추가 맵 |
| 리깅·분류 | 몸·얼굴·맨손·아머·부츠·종아리 부스터는 통합 슈트의 스킨드 메시, 헤어·고글·장비는 강체 본 부착 |

과거 바디+별도 의상 서술 대신 ADR-0008의 2026-09-17 통합 슈트 개정을 적용한다.
머티리얼 수가 적다는 것만으로 드로우콜·게임 성능이 검증됐다고 보고하지 않는다.
전체 캐릭터가 없으면 알려진 파츠 합계를 기록하고 `캐릭터 전체 예산 미확인`으로 구별한다.

## 작업 순서

1. **완료 기준을 대조한다.** 원화 필수 항목, 적용되는 메시·UV·재질 검사, 최신 8방향의 실제 확인 결과를 읽는다.
   결함별 전후 증거와 외관 판정이 미충족이면 보정 단계로 복귀한다. 기술 검사 통과만으로 최종본을 선정하지 않는다.
   복구·진단 목적의 중간 FBX 저장은 가능하지만 `미완료 중간본`으로 표시하고 최종 전달본과 구별한다.
2. **작업본을 저장한다.** 수정본 폴더의 활성 `.blend` 하나와 사용 중인 텍스처·참조 파일을 정리한다.
   새 수정 산출물은 한국 시각을 붙이고, 자동·이전 백업은 `Backups/`로 분리한다.
3. **파일 의존성을 확인한다.** 외부 이미지·링크·패킹 내부 경로를 확인한다. 다른 수정본이나 임시 폴더에 의존하지 않는다.
   Unity에 전달할 Albedo·Normal·추가 맵을 외부 파일로 저장하고, `.blend` 패킹만 된 상태와 구별한다.
4. **저장본을 다시 연다.** 현재 미저장 작업부터 보호하고, 재열기 후 메시·재질·이미지 연결·치수·가시성을 확인한다.
5. **내보낼 대상만 선택한다.** 게임 메시와 필요한 뼈대만 포함하고 기준 고밀도 메시·검수 카메라·조명은 제외한다.
6. **변환 조건을 기록한다.** 크기·축·피벗·삼각형 분할·모디파이어 처리·본 설정을 확인한다.
   스킨드 메시의 변환·Armature를 무조건 적용해 휴식 포즈와 애니메이션을 바꾸지 않는다.
7. **FBX를 내보낸다.** 05에서 베이크에 사용한 분할·노멀 상태를 유지한다. Blender 재질 노드 전체가 FBX로 그대로 전달된다고 가정하지 않는다.
   프로젝트는 애니메이션을 별도 관리하므로 요청하지 않은 클립을 캐릭터 FBX에 함께 굽지 않는다.
8. **빈 장면으로 재반입한다.** 원본 장면을 덮어쓰지 않고 아래 목록을 검사한다. 실패하면 원인 단계로 돌아간다.
9. **FBX와 최종 맵을 Unity에 반입한다.** 전체 흐름 작업에서는 아래 경로·이름 규칙으로 배치하고, Unity 머티리얼에 맵을 연결한 뒤 실제 결과를 검사한다.
   Blender 보정·FBX 전달·폴더 정리만 요청받은 경우에는 해당 산출물까지 처리하고 Unity 단계가 남았다고 보고한다.
10. **최신 링크와 결과를 보고한다.** 캐릭터/파츠 README에 원본 GLB → 수정본 `.blend` → FBX·맵 → Unity 에셋 경로를 연결한다.

### 재반입 검사

- [ ] 내보낸 오브젝트 수·이름·구성과 실제 삼각형 수가 의도와 일치한다.
- [ ] 외곽·실제 크기·앞/뒤·축·피벗이 맞고 거울 반전이나 100배 단위 오류가 없다.
- [ ] UV·노멀·삼각형 분할·재질 할당과 실제 텍스처 연결이 유지된다.
- [ ] Base Color·Normal·필요한 추가 맵을 [05의 채널 기준](05-texturing.md)으로 연결할 수 있다.
- [ ] 스킨드 대상은 본·휴식 포즈·웨이트와 내보낸 애니메이션 범위를 확인했다.
- [ ] 저장본과 재반입 모델을 같은 조건에서 비교했다. 구조·외관을 수정했다면 06의 8방향도 다시 수행했다.

### Unity 반입 검사

Blender의 FBX 재반입 검사를 통과한 뒤, Unity에서 아래를 확인한다.

- [ ] 반입한 FBX·최종 텍스처가 검수한 수정본의 산출물이며 경로가 기록됐다.
- [ ] 실제 Import Settings와 모델의 크기·축·피벗·메시·머티리얼 할당이 맞는다.
- [ ] Unity 머티리얼에 맵을 연결하고 [05의 색 공간·채널 기준](05-texturing.md)과 외관을 확인했다.
- [ ] 스킨드는 실제 리그 방식과 대표 동작(Humanoid 대상이면 Avatar 포함), 강체는 부착·조립 결과를 확인했다. 후속 조립 항목은 별도 표시했다.
- [ ] 장비의 가동 기능이 범위에 있으면 부품 분리·부모 관계·피벗과 대표 위치의 간섭을 확인했다. 유연한 끈·호스는 필요한 변형도 검사했다.
- [ ] Blender와 Unity의 차이가 생기면 조명·셰이더·반입 설정 문제와 원본 메시·맵 문제를 구분했다.

Unity 설정 오류는 이 단계에서 수정한다. 모델·맵 수정이 원인이면 해당 `.blend`의 03/04/05로 돌아가
보정 → 8방향 검수 → FBX·맵 재내보내기 → Unity 재검증을 수행한다.
Blender 재반입은 Unity 검사를 대신하지 않는다. 실행할 수 없으면 `Unity 검증 미실시`와 이유를 보고하고,
전체 흐름 완료로 표시하지 않는다. 오류 출력은 그대로 보존한다.

## 작업본과 Unity 최종본의 이름

| 위치 | 관리 방식 |
|---|---|
| 외부 `3D_Model/<Character>/<Part>/` 또는 공용 파츠 폴더 | 원본·수정본 분리, 수정 산출물에 날짜+시간, 검수는 회차별 폴더 |
| 수정본의 `Exports/` | 어느 수정본에서 나왔는지 알 수 있는 날짜+시간 이름 |
| Unity `Assets/_Project/Art/Characters/<Character>/`의 최종본 | 승인된 한 버전만 유지. **시간 접미사 없이** 고정 이름으로 교체 |

최종 이름은 기존 [asset-pipeline](../asset-pipeline.md)을 따른다.
스킨드는 `SK_<Character>.fbx`, 강체는 `SM_<Character>_<Part>.fbx`, 텍스처는 `T_...`, 재질은 `M_...` 규칙이다.
공용 제트팩은 기존 공용 경로·이름을 확인하고 캐릭터별로 임의 복제하지 않는다.
기존 최종본을 교체할 때 `.meta`를 보존한다. 새 `.meta`는 Unity가 생성하며 직접 작성하지 않는다.

## 완료 보고 형식

아래 `<Character>`는 캐릭터 소속이면 캐릭터명, 공용 장비이면 `public`, 그 외에는 실제 장비/조립체 이름으로 적는다.
Humanoid 검사는 해당 캐릭터용이며 장비·호스 등 모든 스킨드 파츠에 강제하지 않는다.

```text
## 파츠 작업 보고 — <Character> / <Part>

- 상태: 원화 요소 충족·보정 완료 | 미완료·보정 중 | 외부 사유로 중단
- 범위: 고정/변형/가동/혼합, 파츠 보정/리깅/조립/Unity 반입 중 수행한 것
- 원본 보존: 원본 경로·해시, 작업본 경로
- 반입 → 최종: 정점·tris·머티리얼 수, UV, 맵 해상도, Armature
- 수정 내용: 분석 ID별 메시 수정 / 리토폴로지 / 텍스처 수정, 중요한 실제 치수
- 원화 판정: 충족 N / 미충족 N / 미확인 N / 해당 없음 N과 이유
- 시각 결함 판정: ID별 해결 / 잔존 / 미확인, 같은 조건 전후 확대 링크. 사용자 수용 결함은 별도 표시
- 최신 8방향: 회차·실제 확인 결과·발견 문제·보정 내역·이미지 경로
- 기술 검증: 재열기·경로·FBX 재반입·변형 검사·Unity의 실제 결과 또는 미실시
- 예산: 개별 파츠와 알려진 합계, 캐릭터 전체 확인 여부
- 남은 문제·추정·후속 조립: 없으면 없음, 승인받아 미룬 사항은 별도 표시
- 파일 전달 경로: 원본 GLB → Blender 수정본 → FBX·최종 텍스처 → Unity 에셋 (미반입이면 미반입)
- 저장 위치: 원본 / Blender / 텍스처 / 8방향 / FBX / Unity 링크
- 필요한 결정: 있으면 쉬운 설명·이유·선택지, 없으면 없음
```

파츠 8방향 확인은 조립 후 캐릭터 전체 실루엣 검사를 대신하지 않는다.
파일 저장 성공만으로 원화 재현·애니메이션·Unity 검증을 통과했다고 쓰지 않는다.
`8방향 확인 수행`과 `외관 합격`을 구별한다. 결함이 남았으면 보고 첫 상태를 `미완료·보정 중`으로 적는다.
Blender에서 가능한 수정이 남았는데 Unity 연결 문제만을 미완료 이유로 제시하지 않는다.

## 토큰·재작업 절약

- 독립적인 면수·경로 검사는 한 번에 집계하고 `검사 항목 / 기대값 / 실제값 / 실패 원인`만 요약한다. 저장 → 재열기 → 재반입처럼 앞 결과에 의존하는 작업은 순서를 지킨다.
- 상세 로그·설정·수치는 `Notes/`에 보관하고 보고에는 결과와 파일 링크를 제공한다.
- 통과 후 입력 파일·설정이 그대로라면 같은 검사를 이유 없이 반복하지 않는다. 수정 또는 실패가 있으면 영향 검사를 다시 한다.
- 최종본의 실제 상태와 후속 조립을 구분해 다음 작업에서 같은 사실을 재조사하지 않게 한다.

## 조사 근거

확인일: 2026-09-18. 파일명·예산·모듈 구성은 외부 일반 권장값이 아니라 위 프로젝트 문서의 결정이다.

- [Unity 6 — 모델 최적화](https://docs.unity3d.com/6000.0/Documentation/Manual/ModelingOptimizedCharacters.html): 게임 정점·폴리곤·재질과 변형 비용을 구별하는 근거.
- [Unity 6 — URP Lit](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html): 엔진에서 확인할 재질 입력과 채널.
- [Anthropic — Code Execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp): 도구 내부에서 자료를 처리하고 필요한 결과만 반환하는 원리. 새 실행 환경을 필수로 추가하지 않는다.
