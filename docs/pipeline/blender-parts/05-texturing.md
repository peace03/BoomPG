# 05. 텍스처 수정 — 색·결·재질을 원화에 맞추기

[메인 목차](../blender-parts-workflow.md) · 이전: [04. 리토폴로지](04-retopology.md) · 다음: [06. 검수](06-review.md)

## 목적과 입력

확정한 형태와 면 구조에 원화의 색·패턴·표면 결·재질을 맞춘다.
표면 결에는 머릿결·직물뿐 아니라 장비의 도장·금속 결·고무 요철이 포함된다. 로고·경고 띠·패널 경계도 별도 확인한다.
입력은 최종 형태 메시, UV 상태, 원본 이미지와 셰이더, 베이크 원본, 합의한 색 기준이다.
사용 가능한 기존 색·결은 보존하고 달라진 표면에 옮긴 뒤 오류를 보정한다.

사용자 기준: **가는 머릿결 음영·미세 홈·직물 결은 남기고, 큰 그림자와 강한 방향성 반사는 고유색에 고정하지 않는다.**
공용 파츠는 [ADR-0008](../../decisions/ADR-0008-모듈러-캐릭터-구조.md)의 중립색 규칙을 따른다.

## 쉬운 용어

| 용어 | 뜻 |
|---|---|
| UV·섬·심(Seam) | 표면 펼침도 / 펼쳐진 조각 / 펼치기 위해 자르는 경계 |
| 텍셀 밀도 | 같은 실제 면적에 배정된 이미지 픽셀 수. 부위마다 선명도가 다른지 판단 |
| Albedo / Base Color | 물체의 기본 색과 무늬 |
| Normal Map | 표면 방향을 바꿔 작은 홈·결이 빛에 반응하게 하는 이미지. 실제 외곽은 바꾸지 않음 |
| Roughness / Smoothness | 반사가 얼마나 퍼지는지 / 얼마나 매끈한지. 아래 변환은 같은 정의를 쓰는 맵에 적용 |
| Metallic | 금속처럼 빛에 반응할 영역을 지정하는 값 |
| AO | 틈에 주변 빛이 덜 들어가는 정도를 표현한 데이터 |
| 베이크·케이지 | 상세 정보를 새 UV에 옮기기 / 옮길 표면을 찾는 범위를 제어하는 외피 |
| 패딩·밉맵 | UV 조각 밖으로 색을 늘린 여백 / 멀리서 쓸 축소 이미지 |

## 작업 순서

1. **형태·면 구조 완료 여부를 확인한다.** 아직 바뀔 영역이 있으면 최종 UV·베이크를 보류한다.
2. **기존 맵을 분류한다.** 이미지 존재뿐 아니라 실제 색·결, 큰 그림자, 채널·색 공간, 해상도를 확인한다.
3. **UV 유지 여부를 정한다.** 구조가 그대로이고 늘어짐이 없으면 유지한다. 재구성·재질 통합 영역은 새로 펼친다.
4. **체커로 UV를 확인한다.** 바둑판 무늬를 잠시 표시해 정사각형이 늘어나거나 갑자기 크기가 달라지는 곳을 찾는다.
5. **기존 정보를 옮긴다.** UV가 바뀌면 원본과 새 메시를 정렬하고 아래 베이크 절차를 적용한다.
6. **큰 색 영역을 맞춘다.** 주색·보조색·강조색의 면적·경계를 확인한 뒤 머릿결·홈·끈 같은 세부를 다룬다.
7. **재질 반응을 분리한다.** 색·노멀·거칠기·금속성을 각각 수정하고 원화의 하이라이트를 색상 맵에 그대로 칠하지 않는다.
8. **고유색과 조명 뷰를 나눠 확인한다.** 고유색만 보여주는 뷰와 조명이 있는 뷰를 비교한다.
9. **수정본 저장·8방향 검수**를 실행한다. 반대편·뒤·안쪽의 무늬와 색 경계까지 확인한다.
10. 최종 맵을 외부 이미지 파일로 저장하고 해상도·파일 경로·색 공간·채널·사용 셰이더를 기록한다.
    `.blend`와 맵을 [07. FBX 내보내기·Unity 반입](07-export.md)로 인계한다.

## UV를 잘 정리하는 기준

- 장비 예: 원통 경고 띠의 연결과 폭, 패널 로고의 비율·방향, 반복 통풍구의 간격을 확인한다.
  원통 심이나 부품 경계에서 무늬가 끊기고 늘어나는지 3D 표면에서 본다. 의도된 도장 벗겨짐과 AI의 번진 얼룩을 구별한다.
- 가동 부품과 본체의 색을 전사할 때 인접 면의 무늬가 섞이지 않게 한다. 발광부는 실제 발광 영역과 일반 도색을 분리해 확인한다.
- 심은 눈에 덜 띄는 경계·실제 부품 경계를 우선하되 늘어짐과 이음새 수를 함께 비교한다.
- 자동 펼치기는 후보 생성이다. 눈·입·긴 머리 가닥·끈처럼 방향이 중요한 곳의 흐름은 직접 확인한다.
- 비대칭 색·문양·로고가 필요한 면은 겹치지 않는다. 좌우 공유 UV는 같은 색과 디테일을 공유하는 영역만 허용하고 기록한다.
- 베이크 대상 섬의 의도하지 않은 겹침·0면적·과도한 늘어짐을 없앤다.
- 섬 간 간격은 실제 해상도·패딩·축소 표시를 기준으로 잡는다. 모든 모델에 동일한 px 수를 정답으로 고정하지 않는다.
- 노즐 띠처럼 색이 급변하는 경계가 번지면 경계의 UV·패딩·필터링을 확인한다.
  재질별 선택을 사용했다면 실제로 해당 면만 선택됐는지 확인한 뒤 펼친다.
- 여러 부품을 재질1개로 합칠 때는 모든 UV와 맵을 함께 재배치한다. 이미지 파일만 합치고 UV를 그대로 두지 않는다.

## 베이크와 기존 텍스처 보존

보존·전사는 정상 정보를 살리는 절차다. 원본의 번짐·늘어진 로고·잘못 칠해진 음영까지 재사용하면 결함도 그대로 남는다.
리사이즈·패킹·UV 겹침 제거·Normal 강도 감소만 수행한 상태를 텍스처 외관 보정 완료로 표시하지 않는다.

1. 원본과 새 메시의 위치·크기·적용 모디파이어 상태를 맞춘다. 베이크 원본은 수정하지 않고 보존한다.
2. 대상 UV와 이미지 노드를 활성화한다. 빈 이미지나 다른 재질에 굽고 있지 않은지 작은 시험으로 확인한다.
3. 상세→저밀도 전송은 `Selected to Active` 등 대응 기능을 사용한다. 가까운 부품의 색이 섞이면 대상 부품을 분리해 굽거나 케이지·레이 거리를 조정한다.
4. 고유색은 직접광·간접광을 제외한 색상 패스로 옮긴다. **원본 이미지에 이미 칠해진 큰 그림자는 색상 패스만으로 제거되지 않는다.** 해당 영역의 색을 따로 보정한다.
5. UV·삼각형 분할·노멀 기준이 바뀌면 기존 탄젠트 Normal 이미지를 그대로 새 UV에 붙이지 않는다.
   상세 형상에서 다시 굽거나 변환 조건을 확인해 전달하고, 빛 방향을 바꿔 홈이 뒤집히지 않는지 검사한다.
6. Normal 베이크 전에 내보낼 메시의 삼각형 분할과 셰이딩 상태를 정하고 이후 변경하면 영향 맵을 다시 굽는다.
7. 패딩을 포함해 저장하고 축소 화면·이음새에서 검은 선·다른 섬의 색 번짐을 확인한다.
8. 색만 수정했다면 UV·노멀·형태가 그대로인지 확인한 후 영향을 받지 않는 맵은 재베이크하지 않는다.

## 채널·색 공간·Unity 연결

아래는 **URP Lit의 Metallic 워크플로우** 기준이다. 실제 카툰/Shader Graph 셰이더가 다르면 해당 입력 정의를 먼저 확인한다.
`MaskMap`이라는 이름만 보고 HDRP·URP·glTF의 채널을 같다고 취급하지 않는다.

| 데이터 | 작업용 이미지 해석 | URP Lit 연결 |
|---|---|---|
| Albedo | 일반 sRGB 색상 이미지 | Base Map |
| Normal | 색 변환 없는 데이터 | Normal Map, Unity Texture Type을 Normal map으로 설정 |
| MetallicSmoothness | 색 변환 없는 데이터 | R=Metallic, A=Smoothness, Smoothness Source 확인 |
| AO 사용 시 | 색 변환 없는 데이터 | Occlusion Map의 G 채널 |

- glTF 계열 ORM이 `R=AO, G=Roughness, B=Metallic`이면 `MetallicSmoothness.R=ORM.B`,
  `MetallicSmoothness.A=1-ORM.G`로 변환한다. 실제 파일이 이 규약인지 먼저 확인한다.
- 이미 정상 MetallicSmoothness가 제공되면 중복 변환하지 않는다. Smoothness 배율 설정도 결과에 영향을 준다.
- 데이터 맵은 sRGB 변환·색 보정·알파로 RGB가 변하는 처리를 피하고 채널별 값을 확인한다.
- AO는 큰 그림자를 Albedo에 고정하는 대안이 아니다. 사용 시 별도 데이터로 취급한다.
- 최종 맵은 2048×2048 이하. 현재 프로젝트에서 Albedo·Normal은 필수다. 추가 맵은 실제 셰이더 사용에 맞춘다.
- 상대 경로와 패킹을 모두 확인하고 `.blend`를 다시 열어 이미지가 유지되는지 검사한다.

### GLB에서 Unity까지 텍스처 전달

`GLB의 원본 이미지 → Blender에서 보존·보정/베이크 → 최종 외부 이미지 → Unity 머티리얼 연결` 순서다.
수정본 `Textures/`에 최종 맵을 저장하고 07에서 FBX와 함께 전달한다. `.blend` 패킹은 작업본 보존용이다.
FBX 내보내기가 Blender의 모든 셰이더 노드·절차적 무늬·채널 변환을 자동으로 옮긴다고 가정하지 않는다.
노드로 만든 결과는 이미지로 베이크하거나, 실제 Unity 셰이더에서 재현할 설정을 기록하고 Unity에서 확인한다.

## 색이 탁하거나 결이 사라졌을 때

### 결함을 진단하고 실제로 복원하기

1. 결함 ID별로 Albedo만 표시한 화면, Normal을 끈 재질 화면, 최종 재질 화면을 비교한다. 형상 원인은 03/04로 돌려보낸다.
2. 체커와 UV Editor의 `Display Stretch`로 왜곡을 확인한다. `Angle`은 각도 왜곡, `Area`는 면적 비율 차이를 보여준다.
   체커도 늘어지면 UV를 수정하고, 체커가 정상인데 무늬만 찌그러지면 원본 이미지 내용을 확인한다. 겹침 0만으로 UV 품질을 통과시키지 않는다.
3. 색상 맵의 얼룩·고정 그림자는 해당 영역을 다시 칠하거나 정상 영역에서 복제해 복원한다. `Draw`·`Clone`을 사용할 때는 대상 이미지·UV·복제 원본을 확인하고 면 선택/마스크로 정상 로고와 색 경계를 보호한다.
4. 잘못된 Normal 디테일은 해당 영역 수정 또는 보정된 표면에서 재베이크한다. 전체 강도를 낮춰 정상 홈까지 지우는 것으로 대체하지 않는다.
5. 3D 표면에서 이음새·반대편·확대 및 축소 상태를 확인하고 최종 이미지를 저장한다. 같은 조건 전후 비교에서 오류가 남으면 다시 수정한다.

전체 대비·채도·노멀 강도를 낮추거나 Blur/Smear로 결함을 흐리게 만드는 것은 디테일 복원을 대신하지 않는다.
정상 영역에서 복제할 때에도 원본의 그림자·오염이나 반복 무늬를 새 위치로 복사하지 않았는지 확인한다.

| 증상 | 먼저 확인할 원인 | 수정 방향 |
|---|---|---|
| 원화보다 색이 흐림 | 색 공간, 표시 변환, 노출, 조명, 재질 반사 | 동일 비교 조건에서 고유색을 확인한 뒤 색 조정 |
| 머릿결까지 평평해짐 | 큰 음영을 지우면서 미세 결도 제거했는지 | 결 방향·미세 음영을 복원, 큰 방향성 명암과 분리 |
| 앞은 맞고 뒤가 다름 | 뒷면 UV·패턴 누락, 투영 사각지대 | 뒤·안쪽을 별도로 보정하고 8방향 재검사 |
| 홈이 튀어나와 보임 | Normal 방향·채널, 탄젠트·삼각형 분할 불일치 | 엔진 규약과 다시 비교해 변환/재베이크 |
| 경계가 톱니·줄무늬로 보임 | UV 선택·겹침·패딩·해상도·축소 필터링 | 경계 원인을 고친 뒤 해당 맵 재생성 |

검은 렌즈를 색만 보고 금속 또는 투명 유리로 확정하지 않는다. 투명도는 내부 구조와 게임 외관을 바꾸므로 불명확하면 설명 후 묻는다.
색을 맞추려고 발광을 임시로 넣거나, 전체 채도를 올려 조명 문제를 가리지 않는다.
원화는 목표 참고 그림이다. 원화 이미지 한 장을 그대로 UV 텍스처로 덮어 씌우지 않는다.

## 합격 기준과 인계

- [ ] 원화의 주색·보조색·패턴 위치와 앞뒤 연결이 맞는다.
- [ ] 텍스처 결함 ID별 전후 확대에서 번짐·왜곡·잘못된 음영이 해결됐고 정상 디테일은 유지됐다. 원본 전사만으로 통과시키지 않았다.
- [ ] 보존할 머릿결·홈·직물 결이 남아 있고, 큰 그림자·강한 반사가 Albedo에 고정되지 않았다.
- [ ] UV 늘어짐·의도하지 않은 겹침·번짐을 체커·확대·축소 뷰에서 확인했다.
- [ ] 고유색/재질 뷰를 구별하고 마지막 수정 후 8방향을 모두 확인했다.
- [ ] 실제 맵 해상도·색 공간·채널 역할·경로·패킹이 기록됐다.
- [ ] FBX와 함께 전달할 최종 외부 이미지가 저장됐고 Unity 셰이더의 입력과 대응한다.
- [ ] 베이크에 사용한 표면·UV·삼각형 분할과 내보낼 상태가 일치한다.

UV 늘어짐·심·배치 문제는 이 단계에서 다시 보정한다. 면 연결 자체를 바꿔야 해결되는 문제면 04로, 실제 두께·외곽 문제면 03으로 돌아간다.
Unity 화면을 확인하지 않았다면 Blender 색 검증과 Unity 검증을 분리해 보고한다.

## 토큰·재작업 절약

- 기존 UV와 텍스처가 합격이면 재작성하지 않는다. 변경된 영역과 영향을 받는 채널만 처리한다.
- 베이크 설정을 저장하고 작은 시험으로 선택·케이지·색 경계를 확인한 뒤 최종 해상도를 굽는다.
- 픽셀 전체를 대화에 나열하지 않고 해상도·채널 통계·오류 좌표·결과 경로를 반환한다.
- 원화·UV·기존 맵·수정 목표를 한 묶음으로 전달해 반복 설명을 줄인다.
- 이미지 생성 기능을 쓴 결과도 UV·패턴·큰 음영 기준으로 검사한다. 무료·정확한 UV 보존·토큰 절약을 보장한다고 가정하지 않는다.

## 조사 근거

2026-09-18 추가 검색 근거:
[Blender — UV Overlays](https://docs.blender.org/manual/en/latest/editors/uv/overlays.html)는 각도/면적 늘어짐 진단,
[Texture Paint Tools (3.6)](https://docs.blender.org/manual/en/3.6/sculpt_paint/texture_paint/tools.html)는 Draw·Clone·Mask의 기능 근거다.
후자는 구버전 기능 설명이므로 설치 버전의 브러시·메뉴·대상 설정을 확인해 사용한다.
진단 순서·정상 영역 보호·결함별 합격 기준은 이 작업에 적용한 운영 규칙이다.

확인일: 2026-09-18. 미세 결 유지·큰 그림자 제거는 사용자 스타일 요구이며, 아래 재질 분리 원리와 함께 적용한다.

- [Blender 5.2 — Seams](https://docs.blender.org/manual/en/5.2/modeling/meshes/uv/unwrapping/seams.html): 펼침 경계와 늘어짐의 관계.
- [Blender — UV Operators](https://docs.blender.org/manual/en/5.0/modeling/meshes/editing/uv.html): 자동 투영·펼침·늘어짐 조정의 선택지.
- [Blender 5.2 — Render Baking](https://docs.blender.org/manual/ko/5.2/render/cycles/baking.html): 베이크 대상, 표면 대응, 케이지, 패딩.
- [Blender — Bake Influence](https://docs.blender.org/manual/id/5.0/render/cycles/baking.html): 색상 패스와 직접광·간접광 분리.
- [Adobe — PBR Guide, Part 2](https://www.adobe.com/learn/substance-3d-designer/web/the-pbr-guide-part-2): 고유색·거칠기·금속성·미세 가림을 구분하는 원리. 물리 기반 수치를 모든 카툰에 일괄 강제하지 않는다.
- [Adobe — Color Management](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/features/color-management/color-management): 색상 채널과 데이터 채널, 표시 변환의 구별.
- [Unity 6 — URP Lit](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html): 실제 셰이더 입력과 Smoothness Source. 프로젝트의 [기존 맵 대응](../asset-pipeline.md)도 함께 확인한다.
