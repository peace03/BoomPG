# 06. 반복 검수 — 수정 묶음마다 8방향 확인

[메인 목차](../blender-parts-workflow.md) · 이전: [05. 텍스처](05-texturing.md) · 다음: [07. 내보내기](07-export.md)

## 목적과 입력

수정한 부위가 좋아졌는지와 다른 방향에 새 문제가 생겼는지를 함께 확인한다.
입력은 저장한 수정본, 원화 분석표, 이번 수정 ID, 이전 검수 결과와 촬영 설정이다.

2026-09-18 사용자 합의: **작업 중에는 해당 부위를 확인하고, 수정 묶음이 끝날 때마다 8방향 전수 확인한다.**
최종본은 8방향·원화 비교·필요한 확대 검수를 모두 수행한다. 검수 이미지가 생성된 것과 실제로 확인한 것은 구별한다.

## 쉬운 용어

| 용어 | 뜻 |
|---|---|
| 직교 뷰 | 거리에 따른 원근 축소 없이 보여주는 화면. 외곽·비율 비교에 사용 |
| 원근 뷰 | 가까운 것이 크게 보이는 화면. 원화 카메라와 맞춰 비교할 때 사용 |
| 와이어프레임 | 표면의 점·선·면 연결을 표시한 화면 |
| 핀칭 | 선이 몰리거나 면이 잘못 연결되어 표면이 집힌 것처럼 보이는 현상 |
| 검수 연락판 | 여러 방향을 한 장에 배치한 비교 이미지. 작게 보이는 결함은 별도 확대 필요 |

## 검수 시점과 수정 묶음

- 수정 시작 전에 `문제 ID / 대상 부위 / 이번에 바꿀 것 / 확인할 결과`를 정한다.
  예: `G01·G02 / 렌즈·프레임 / 높이·깊이 보정 / 앞·옆 실측과 전체 외곽`.
- 편집하는 동안에는 해당 부위 확대·단면·와이어프레임으로 즉시 확인한다.
- 서로 관련된 보정이 끝나 저장한 시점에 8방향을 확인한다. 메시 보정, 리토폴로지, 텍스처 완료는 각각 검수 시점이다.
- 여러 독립 문제를 전체 작업 하나로 묶어 중간 8방향 검수를 생략하지 않는다.
- 변경 없이 동일한 저장본을 최종 후보로 선정했다면 그 저장본의 최신 검수 증거를 재사용할 수 있다.
  **그 뒤 메시·UV·텍스처·재질을 바꾸었다면 새 회차**를 만든다.

## 작업 순서

1. **검수 상태를 고정한다.** 수정본을 저장하고 파일 경로·시각·해시 또는 변경 식별값을 기록한다.
   모든 이미지는 같은 메시·텍스처 상태에서 생성한다.
2. **비교 조건을 고정한다.** 파츠의 정면 축, 카메라 위치·대상·직교 크기/초점거리,
   해상도·조명·배경·노출·표시 변환을 기록한다. 앞대각·뒤대각의 좌우 방향도 명시한다.
3. 아래 8방향을 전부 저장한다. 화면 밖으로 잘리거나 부품이 가려진 이미지는 다시 촬영한다.
4. 원화와 같은 원근 시점의 비교 화면을 추가한다. 직교 화면과 원근 원화의 차이를 곧바로 메시 오류로 판단하지 않는다.
5. 두께·렌즈 단차·손가락·끈·노즐 등 전체 화면에서 작은 부위는 확대·단면·측정 증거를 추가한다.
6. 색 문제는 고유색만 보여주는 화면과 재질·조명이 있는 화면을 나눠 본다. 면 구조는 와이어프레임으로 확인한다.
7. **8방향 이미지를 실제로 열어 모두 확인한다.** 연락판은 비교를 돕는 도구다. 판별하기 작은 방향은 원본 크기로 연다.
8. 방향별 발견 사항과 원화 분석 ID 판정을 기록하고, 미충족 원인에 해당하는 단계로 돌아간다.
9. 보정 뒤 새 회차에서 다시 8방향을 확인한다. 전 회차의 개선과 새 결함을 함께 비교한다.

```text
8방향확인/<YYYYMMDD_HHMMSS>/
├── Left_<시각>.png       # 좌
├── Right_<시각>.png      # 우
├── Front_<시각>.png      # 앞
├── Back_<시각>.png       # 뒤
├── Top_<시각>.png        # 위
├── Bottom_<시각>.png     # 아래
├── FrontDiag_<시각>.png  # 앞대각
├── BackDiag_<시각>.png   # 뒤대각
└── Review_<시각>.md      # 조건·판정·필요한 확대 이미지 링크
```

## 무엇을 확인하는가

| 대상 | 확인 내용과 증거 |
|---|---|
| 전체 형태 | 원화 실루엣·덩어리·폭/높이/깊이. 같은 조건의 전후 비교 |
| 두께·단차 | 좌·우·위·아래·대각선, 필요한 단면·측정. 정면 한 장으로 판정하지 않음 |
| 빈 공간·결합 | 뒤·아래·뒤대각에서 막힌 구멍, 관통, 떠 있는 연결부 |
| 색·패턴·표면 결 | 로고·경고 띠·도장·직물·머릿결의 연속성, 누락, 이음새, 방향, 큰 그림자와 미세 결의 구별 |
| 면과 재질 반응 | 핀칭·반사 찌그러짐·역면, Normal 방향, 광원 이동 시 외관 |
| 변형 | 스킨드 파츠의 대표 포즈. 8방향 정지 화면에 추가하며 이를 대신하지 않음 |
| 장비 조립·가동 | 부착면·피벗·인접 부품 간섭. 가동 기능이 있으면 닫힘·열림·중간 위치도 확인 |
| 게임 화면 | 정해진 게임 카메라 거리에서 디테일이 읽히는지. 조건 미정이면 미확인으로 기록 |

## 기록과 실패 시 복귀

### 결함별 전후 판정

원화 분석표와 같은 작업 기록에 아래 항목을 연결한다. 별도 중복 보고서를 만들 필요는 없다.

| 문제 ID·위치 | 목표 모습 | 원인과 진단 증거 | 실제 수정 | 수정 전·후 확대 경로 | 결과·잔여 문제·다음 행동 |
|---|---|---|---|---|---|
| 예: D01·왼쪽 추진기 외벽 | 의도하지 않은 함몰 없는 곡면 | 단색·단면에서도 패임 확인 | 국소 정점·면 연결 보정 | 같은 조건의 전후 이미지 | 패임 잔존 → 미충족, 목표 곡면 재조정 |
| 예: D02·패널 로고 | 비율이 맞고 번짐 없는 문양 | 체커 정상, Albedo 왜곡 | 해당 무늬 복원 | Albedo·재질 전후 확대 | 왜곡 해소와 경계 유지 확인 후 충족 |
| 예: D03·브래킷 | 열린 구멍과 벽 두께 유지 | 단면에서 구멍 막힘 확인 | 국소 면 재연결 | 뒤·옆·단면 전후 | 개구부·두께·면 교차 재검사 |

- 카메라·대상 크기·조명·노출·표시 변환을 맞춘 전후 확대 이미지를 실제로 열어 비교한다.
  크기·방향 변경이 작업에 포함되면 비교용 사본/카메라에서 화면상 크기·방향을 맞추고 조건을 기록한다.
- 함몰은 단색·단면과 최종 재질, 텍스처 오류는 Albedo 단독과 최종 재질로 판정한다.
  전체 8방향은 주변 악화를 확인하고, 확대 비교는 개별 결함의 해결을 입증한다. 서로 대체하지 않는다.
- 판정은 기존 `충족 / 미충족 / 미확인 / 해당 없음`을 사용한다. `조금 개선됨`은 목표에 못 미치면 `미충족`이다.
  설정값·정점 수·파일 해시가 바뀌었다는 사실은 시각적 개선 증거가 아니다.
- 개선이 보이지 않으면 원인 진단과 수정 방법을 바꾼다. 새 결함이 생기면 되돌리거나 함께 해결한 뒤 재검수한다.
- 발견한 결함은 기록으로 끝내지 않고 다음 수정 대상으로 연결한다. 원래부터 있던 오류라는 이유로 제외하지 않는다.

각 방향에 `확인한 파일 / 실제 확인 여부 / 문제 ID·위치 / 전회 대비 결과`를 남긴다.
분석표 판정은 `충족 / 미충족 / 미확인 / 해당 없음(이유)`으로 유지한다.
자동 파일 검사·치수 계산 결과와 사람이 볼 수 있는 시각 증거를 구별한다.

| 실패 원인 | 돌아갈 단계 |
|---|---|
| 원화가 서로 다르거나 중요한 구조·실제 크기가 미정 | [01. 원화 분석](01-reference-analysis.md)에서 쉬운 설명과 선택지로 확인 |
| 외곽·비율·실제 두께·결합 오류 | [03. 메시 수정](03-mesh-editing.md) |
| 면 흐름·삼각형 분할·변형 문제 | [04. 리토폴로지](04-retopology.md), 웨이트 원인도 구별 |
| UV·고유색·패턴·베이크·재질 문제 | [05. 텍스처](05-texturing.md) |
| 저장·누락 파일·내보내기 오류 | [07. 내보내기](07-export.md) |

필수 항목의 미충족·미확인이 남으면 완료가 아니다. 반복 횟수나 작업 시간을 이유로 기준을 낮추지 않는다.
도구 오류 또는 답변이 필요한 상황은 중간본과 남은 항목을 저장한다. **질문을 시간 경과로 건너뛰거나 자동 승인하지 않는다.**
단, 장애와 무관한 승인 범위의 보정은 계속한다. 외관 미충족을 기술 검사 통과나 Unity 미연결 뒤에 숨기지 않는다.
결함을 유지하기로 사용자가 명시한 경우 `미충족·사용자 수용`으로 구별하고 합격 건수에 넣지 않는다.

## 합격 기준과 인계

- [ ] 최종 수정 이후 동일 상태의 8방향을 모두 실제로 확인했다.
- [ ] 원화 시점 비교, 필요한 확대·단면·측정으로 핵심 특징을 판정했다.
- [ ] 모든 적용 원화 요소가 충족됐고 해당 없음·추정의 근거가 있다.
- [ ] 변경 전후와 새로 생긴 결함을 확인했으며 미충족을 숨기지 않았다.
- [ ] 사용자 지적 및 발견 결함의 ID마다 같은 조건 전후 확대 증거와 잔여 문제 판정이 있다. 개선이 없는 항목을 완료로 넘기지 않았다.
- [ ] 적용되는 변형 검증과 후속 조립·Unity 미실시 상태가 구별되어 있다.
- [ ] 이미지·설정·판정·수정본 경로가 같은 회차로 연결되어 있다.

통과한 저장본을 07로 인계한다. 내보내기 과정에서 모델을 수정하면 영향을 받는 단계와 이 검수를 다시 수행한다.

## 토큰·재작업 절약

- 촬영 설정을 재사용해 반복 카메라 조정과 조건 차이에 대한 설명을 줄인다.
- 원본 이미지는 로컬에 보관하고 대화에는 방향별 짧은 판정과 변경 ID, 필요한 확대 증거를 전달한다.
- 먼저 연락판으로 비교하되 8방향의 판독성을 확보한다. 이미지 축소로 결함을 놓치는 것은 절약으로 취급하지 않는다.
- 실패 ID 중심으로 다음 보정을 정한다. 이미 합격한 부위의 설명·원본 데이터 전체를 매번 다시 출력하지 않는다.
