# 02. 반입 점검 — 원본과 현재 상태 보존

[메인 목차](../blender-parts-workflow.md) · 이전: [01. 원화 분석](01-reference-analysis.md) · 다음: [03. 메시 수정](03-mesh-editing.md)

## 목적과 입력

원본 모델·원화·텍스처를 보존하고, 변경 전 메시·재질·리깅 상태를 측정한다.
입력은 사용자 `.glb`, 관련 파일, 01단계 분석표다. 이 단계에서는 외형을 보정하지 않는다.
파일 흐름 중 **GLB → Blender** 구간이며, 결과는 원본 GLB와 최초 반입 `.blend`, 별도 수정용 `.blend`다.

## 쉬운 용어

| 용어 | 뜻 |
|---|---|
| 정점·면·삼각형 수 | 표면을 이루는 점·조각 수. 게임 예산은 최종 삼각형 수(tris)로 비교 |
| UV | 3D 표면을 2D 이미지의 어느 위치에 붙일지 정한 펼침도 |
| 노멀 | 표면이 향하는 방향. 잘못되면 검거나 뒤집힌 것처럼 보임 |
| Armature·웨이트 | 뼈대 / 각 점이 어느 뼈를 얼마나 따라갈지 정한 비율 |
| Shape Key | 눈 감기처럼 정점 위치의 다른 상태를 저장한 변형 데이터 |
| 해시·패킹 | 파일 내용의 지문 / 외부 이미지를 Blender 파일 안에도 넣는 것 |

## 폴더와 파일

```text
3D_Model/<Character>/
├── README_<날짜_시간>.md
├── <Part>/
│   ├── 00_Original/
│   │   ├── <Character>_<Part>_Original.blend
│   │   └── <원본 GLB·원화·원본 텍스처>
│   ├── 01_Revision_<Stage>/
│   │   ├── <Character>_<Part>_<Stage>_<날짜_시간>.blend
│   │   ├── Textures/
│   │   ├── Sources/
│   │   ├── Notes/
│   │   ├── Exports/
│   │   ├── Backups/
│   │   └── 8방향확인/<날짜_시간>/
│   └── 02_Revision_<Stage>/
└── <다른 파츠>/
```

- 날짜·시간은 한국 시간 `_YYYYMMDD_HHMMSS`다. 번호는 파츠별로 증가한다.
- 폴더 하나에 활성 `.blend` 하나와 그 파일이 사용하는 관련 파일을 둔다.
- `00_Original`은 덮어쓰지 않는다. 원본 GLB·원화·이미지의 해시를 기록한다.
- `Textures`는 현재 사용 맵, `Sources`는 원화·베이크 입력, `Notes`는 분석·변경·검증 기록이다.
- `.blend1`, 이전 세션 사본·압축 보관본은 `Backups`에 둔다. 실패한 시도도 상태를 적고 보존한다.
- 수정본 이미지 경로는 해당 폴더 내부 상대 경로로 연결하고 패킹한다. 패킹 내부 경로도 확인한다.
- 공용 장비는 `3D_Model/public/<Part>/`에 같은 구조를 사용한다.
- 현행 파츠 구성은 [ADR-0008](../../decisions/ADR-0008-모듈러-캐릭터-구조.md)의 최신 개정 표를 따른다.
  이미 존재하는 Body·Clothing 폴더는 작업 이력이며 새 구조를 적용한다는 이유로 삭제·병합하지 않는다.
- 작업 저장본에는 시각을 붙이고, Unity 저장소에 들어가는 확정본은 [07의 고정 이름](07-export.md)을 쓴다.

## 반입 순서

1. 실행 중인 Blender의 파일·선택 대상·저장되지 않은 변경을 확인한다. 변경이 있으면 사본을 보존한다.
2. 입력 파일의 존재·확장자·읽기 가능 여부를 확인한다. 새 작업 폴더를 만들고 원본을 복사·해시 검증한다.
3. GLB를 Blender로 반입하고 수정 전 `.blend`를 저장한다. GLB에 포함된 이미지의 실제 연결·내용을 확인하고 원본 상태를 보존한다.
   과거 USD 계열 파일은 기존 원본으로 보관한다. 이번 작업의 GLB가 없으면 입력 누락을 알리고, 다른 형식을 GLB로 간주해 진행하지 않는다.
   존재하지 않는 `.blend` 경로를 추정하거나 확장자만 바꿔 변환했다고 처리하지 않는다.
4. 아래 표를 한 번 측정해 `Notes/Intake_<날짜_시간>.json` 또는 Markdown에 저장한다.
5. 재질을 켠 뷰, 단색 형태 뷰, 와이어프레임으로 결함 위치를 분류하고 분석표 ID와 연결한다.
6. 수정용 복사본을 저장하고 적용할 작업 범위를 정한다. 전체 재구성을 후보로 선택한 경우 [03의 확인 절차](03-mesh-editing.md#수정-범위-선택)를 따른다.

| 분류 | 측정·확인 항목 |
|---|---|
| 형상 | 정점·삼각형·메시 오브젝트 수, 연결 덩어리, 단위·폭·높이·깊이, 변환·피벗·정면 축 |
| 결함 | 중복·퇴화 면, 떨어진 점/선, 뒤집힌 면, 열린 경계, 자기 교차, 뭉친 부품 |
| UV | 레이어 수, 누락, 겹침, 늘어짐, 0면적 섬, 활성 UV |
| 재질 | 슬롯 수, 실제 셰이더 연결, 투명도, 미사용 슬롯 |
| 이미지 | 경로·패킹, 해상도·색 공간, 채널 역할, 실제 내용, 누락 |
| 변형 | Armature·본 이름, 웨이트, Shape Key, 모디파이어, 애니메이션·휴식 포즈 |
| 부품 구성·가동 | 본체·덮개·노즐·끈·호스 등의 분리 상태, 부모 관계, 부착점·회전축·피벗, 고정/가동/변형 범위 |
| 예산 | 현재 파츠와 이미 알려진 다른 파츠 합계. 모르는 파츠를 0으로 계산하지 않음 |

## 잘못된 판정 방지

- 수정 전에 결함 부위 확대 이미지를 남기고 [06의 결함 기록](06-review.md#결함별-전후-판정)에 연결한다.
  재질 포함 뷰, 텍스처·Normal을 끈 단색 뷰, 조명 없는 Albedo 뷰를 비교해 실제 형상과 맵의 오류를 분리한다.
  단색에서도 남는 명암은 와이어프레임·단면·메시 노멀을 추가 확인하며, 한 화면만으로 함몰 원인을 단정하지 않는다.
- UV나 하드 에지 경계에서 점이 분리된 모델은 경계 에지가 많다. 숫자만으로 전부 구멍이라고 단정하지 않는다.
- 노즐 입구·옷 끝·렌즈 가장자리 같은 의도된 열린 면을 자동으로 막지 않는다.
- 흰색1픽셀 이미지도 정상적으로 로드될 수 있다. “이미지 존재”와 “쓸 수 있는 텍스처”를 구별한다.
- 원본에 뼈대·웨이트가 이미 있으면 보존한다. 다시 자동 리깅하는 것을 기본 동작으로 삼지 않는다.
- 읽기와 점검을 위해 모디파이어를 적용하거나 전체 정점을 용접하지 않는다.

## 합격 기준과 인계

- [ ] 원본 내용과 최초 반입 상태를 복구할 수 있다.
- [ ] 입력 GLB와 원본/수정용 `.blend` 경로가 연결되어 있고, 후속 편집은 수정용 `.blend`에서 이어간다.
- [ ] 파일·텍스처·치수·변형 데이터의 실제 상태와 누락이 기록됐다.
- [ ] 눈에 보이는 형태 문제와 메시 구조 문제, 재질 문제를 구별했다.
- [ ] 수정 대상과 보존 대상을 이름·그룹·분석 ID로 특정했다.

원본 읽기 실패나 핵심 데이터 누락은 통과로 바꾸지 않는다. 읽을 수 있는 자료는 보존하고 누락 내용을 보고한다.
폴더 정리만 요청받았다면 이동 전후 경로·해시·모든 `.blend` 재열기와 이미지 경로를 검사하고 종료한다.
그 과정에서 과거 모델의 시각 검수를 새로 통과한 것으로 기록하지 않는다.

## 토큰·재작업 절약

- 치수·면수·경로·재질 목록은 Blender에서 한 번에 계산하고 요약만 대화로 반환한다.
- 전체 정점·픽셀 배열과 원본 바이너리를 대화에 출력하지 않는다. 상세값은 로컬 점검 파일에 보존한다.
- 텍스처 해시가 같고 입력 파일이 바뀌지 않았으면 동일 반입 점검을 반복하지 않는다.
- 새 파츠를 처리할 때 파일 이름·단위·본 존재를 이전 파츠의 값으로 재사용하지 않는다.
