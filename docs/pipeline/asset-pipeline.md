# 에셋 파이프라인 (Asset Pipeline)

> 현재 상태: 규격 확정 · 첫 캐릭터(로카) 반입 진행 중

## 1. 전제

3D 모델은 **VARCO 3D**로 생성합니다 (README 참조).
AI 생성 모델은 폴리곤 수·머티리얼 구성·스케일·피벗·본 구조가 매번 다르므로,
규격 없이 반입하면 런타임 성능과 애니메이션이 모두 무너집니다.

캐릭터 모델의 외형·컬러 테마 기준은 [design/worldbuilding.md](../design/worldbuilding.md) 3장입니다.
생성 프롬프트를 쓸 때 그 문서의 외형 묘사를 기초 자료로 삼으십시오.

| 캐릭터 | 성별 | 컬러 테마 | 실루엣 특징 |
|---|---|---|---|
| 스파크 (`Spark`) | 여 | **검정·차콜 베이스** + 빨강·노랑 하이라이트 | 날렵한 스포츠 웨어, 바이저 고글, **종아리 부스터** |
| 로카 (`Rocca`) | 남 | 핫 오렌지 & 레드 | 과장된 폭격기 점퍼, 탄띠, 팔목 보조 발사기 |
| 기즈모 (`Gizmo`) | 여 | 시안 & 다크 퍼플 | 비대칭 테크웨어, 오른팔 전체를 덮는 갈고리 건틀릿 |

> 스파크는 **검은색이 넓은 면적**을 차지하고 빨강·노랑은 머리카락과 장비 하이라이트에만
> 들어갑니다. 로카의 오렌지·레드와 색 계열이 가까우므로, 스파크를 전체적으로 밝게 칠하면
> 두 캐릭터가 뭉개집니다. **명도 대비를 유지하십시오.**

위 실루엣 특징은 **스킨이 바꿀 수 없는 불변 요소**입니다
([ADR-0006](../decisions/ADR-0006-캐릭터-실루엣-불변.md)).
스킨은 색·텍스처·패턴·재질과 실루엣에 영향을 주지 않는 소품만 바꿉니다.
전체 비율·어깨 폭·위 표의 돌출 요소는 고정입니다.

## 2. 반입 규격 (확정 — D-012)

근거와 검토 과정은 [ADR-0007](../decisions/ADR-0007-캐릭터-에셋-반입-규격.md)에 있습니다.

| 항목 | 값 | 비고 |
|---|---|---|
| 파일 포맷 | **FBX (Binary)** | glTF는 기본 임포터가 없다 |
| 단위 스케일 | **1 unit = 1 m** | 내보낼 때 스케일 100 배율에 주의 |
| 피벗 | **발밑 원점** | (0,0,0)에서 +Y로 선다 |
| 정면 축 | **+Z** | |
| 폴리곤 | **15,000 tris 이하** (1체) | 8인 합계 120,000. LOD 없이 간다 — M2 실측 후 재판단 |
| 텍스처 해상도 | **2048 × 2048 상한** | Unity 임포트 설정으로 하향 가능 |
| 텍스처 채널 | Albedo · Normal (필수) / MaskMap (선택) | 카툰 렌더라 Metallic·Smoothness 비중이 낮다 |
| 머티리얼 슬롯 | **캐릭터당 1개** (최대 2개) | 8인 × 슬롯 수만큼 드로우콜이 늘어난다 |
| 리깅 | **Unity Humanoid** | 세 캐릭터가 애니메이션을 공유하기 위한 전제 |
| 애니메이션 | 모델 파일에 포함하지 않음 | 별도 관리하여 3종이 공유한다 |

> **Humanoid 리깅이 이 규격의 핵심입니다.** 세 캐릭터는 기본 스펙이 100% 동일하고
> (gdd 5.1) 스킬 하나만 다르므로, 걷기·점프·낙하·피격 같은 기본 동작을 전부 공유합니다.
> Generic으로 가면 애니메이션 작업량이 3배가 됩니다.
>
> **기즈모의 건틀릿은 메시로 만들고 본 구조는 좌우 대칭을 유지하십시오.**
> 극단적 비율을 본으로 만들면 리타게팅 시 어색해집니다.
> 실루엣의 비대칭([ADR-0006](../decisions/ADR-0006-캐릭터-실루엣-불변.md))은 메시가 담당합니다.

### 2.1 VARCO 3D 출력 특성 (2026-09-16 실측)

로카(`SK_Rocca.fbx`, 14.5 MB)를 분석해 확인한 내용입니다.

| 항목 | 실측값 | 판정 |
|---|---|---|
| 포맷 | FBX Binary (Kaydara) | 일치 |
| 리깅 | **포함됨** — Mixamo 표준 본 22개 | **자동 리깅 후처리 불필요** |
| 본 명명 | `Hips`·`Spine/1/2`·`Neck`·`Head`·`LeftArm`·`LeftForeArm`·`LeftUpLeg` 등 | Unity Humanoid 자동 매핑 규칙 |
| 스키닝 | Skin 1 + Cluster 22 + BindPose 3 | 정상 바인딩 |
| 본 대칭 | Left/Right 짝 완전 일치 | ADR-0006 요건 충족 |
| 손가락 본 | 없음 | Humanoid 옵션이므로 무방 |
| **폴리곤** | **15,000 tris** (정점 11,782) | 규격 상한과 동일 |
| 텍스처 | **FBX에 임베드** — 2048×2048 PNG 3장 | 일치 |
| 텍스처 구성 | `base_color` · `normal` · **`orm`** | 아래 주의 |

VARCO 3D의 기본 출력이 **15,000 tris** 수준으로 보입니다. 최초 규격은 8,000이었으나
이 실측을 근거로 15,000으로 개정했습니다 (ADR-0007 개정 이력 참조).

### 2.1.1 산출물이 여러 벌로 온다

VARCO 3D 워크플로우는 한 캐릭터에 대해 **여러 단계의 파일**을 함께 내려줍니다.
로카의 경우 다음과 같았습니다.

| 파일 | 폴리곤 | 리깅 | 용도 |
|---|---|---|---|
| `SK_Rocca.fbx` (14.5 MB) | 15,000 tris | **있음** (Mixamo 본 22개) | **← 이것을 쓴다** |
| `Roca_Retopo.fbx` (7.7 MB) | 7,752 tris | **없음** (본 0개) | 리토폴로지 중간 산출물 |
| `Roca_Retopo_Textures/` | — | — | 텍스처 5장 (아래) |

**폴리곤이 적다고 Retopo 파일을 쓰면 안 됩니다.** 본이 하나도 없어 애니메이션을 붙일 수 없습니다.

> **워크플로우 개선 여지** — 리토폴로지된 메시(7,752)에 리깅을 하면 폴리곤 절반으로
> 같은 결과를 얻습니다. VARCO 3D에서 그 조합을 받을 수 있는지, 아니면 Retopo FBX를
> Mixamo 등에 올려 자동 리깅할 수 있는지 다음 캐릭터에서 시도해 보십시오.
> 성공하면 규격을 8,000으로 되돌릴 수 있습니다.

### 2.1.2 텍스처는 별도 파일로도 제공된다 — 추출하지 말 것

FBX에 임베드된 텍스처를 Unity의 `Extract Textures...` 로 빼낼 수도 있지만,
**원본 폴더에 이미 개별 PNG로 들어 있습니다.** 그쪽을 복사하는 편이 간단하고 확실합니다.

| 원본 파일 | 복사 후 이름 | URP Lit 슬롯 |
|---|---|---|
| `Roca_BaseColor.png` | `T_Rocca_Albedo.png` | Base Map |
| `Roca_Normal.png` | `T_Rocca_Normal.png` | Normal Map |
| `Roca_MetallicSmoothness.png` | `T_Rocca_MetallicSmoothness.png` | Metallic Map |
| `Roca_AO.png` | `T_Rocca_AO.png` | Occlusion Map |
| `Roca_ORM.png` | **복사하지 않음** | — |

전부 2048×2048 이라 규격을 만족합니다.

> **`MetallicSmoothness` 가 함께 제공되므로 ORM 문제는 발생하지 않습니다.**
> ORM(glTF·Unreal 표준: R=Occlusion, G=Roughness, B=Metallic)은 URP Lit의
> Metallic Gloss Map(R=Metallic, A=Smoothness)과 채널 배치가 다르고 Roughness는
> Smoothness의 반대값이라, 그대로 연결하면 거친 표면이 금속처럼 보입니다.
> **이미 변환된 `MetallicSmoothness` 를 쓰고 `ORM` 은 무시하십시오.**

복사한 뒤 Unity에서 `Ctrl+R` 로 새로고침하고, **`T_<캐릭터>_Normal` 의 Texture Type 을
`Normal map` 으로 바꾸십시오.** 이 설정은 FBX가 아니라 **PNG 파일을 선택했을 때**
Inspector 맨 위에 나타납니다.

### 2.2 AI 3D 생성의 한계와 대응 (2026-09-16 · VARCO 2차 시도 실패 분석)

VARCO 3D 2차 시도에서 **세 캐릭터 모두 반입 불가 수준**으로 나왔습니다.
증상을 원인별로 갈라 두어야 다음 시도에서 같은 실패를 반복하지 않습니다.

| 증상 | 원인 |
|---|---|
| 메시가 뭉개짐 | **`Remesh` 노드가 100,000 → 8,000 으로 92% 를 깎았다.** Remesh 없이 돌린 1차 시도(30,000)가 오히려 나았다 |
| 얼굴 메시에 머리카락 텍스처가 그려짐 | 메시 형태가 틀어진 상태에서 `Texture3D` 가 정면 이미지를 투영해 **UV 가 밀렸다** |
| 머리카락·의상이 덩어리로 뭉침 | **단일 정면 이미지로는 얇고 돌출된 구조를 복원할 수 없다.** 생성 모델의 구조적 한계 |
| 팔·겨드랑이·옆구리가 서로 붙어 뭉침 | **`Generate3D` 의 `tPose` 를 켜지 않았을 가능성이 높다.** 팔이 몸통에 붙은 포즈로 생성되면 그 사이가 물갈퀴처럼 메워진다. `Rig` 노드의 전제 조건이기도 하다 |

#### 2.2.0 노드 파라미터 점검표 — 결과를 바꾸는 것들

`polygonCount` 만 만지느라 놓친 것들입니다. **`Generate3D` 에서 아래를 먼저 확인하십시오.**

| 파라미터 | 설정값 | 이유 |
|---|---|---|
| `tPose` | **1** | 리깅 대상 캐릭터는 필수. 끄면 팔이 몸에 붙어 겨드랑이가 뭉치고 `Rig` 가 본을 잘못 심는다 |
| `generateTexture` | **1** | 이걸 켜면 `Texture3D` 를 따로 붙일 이유가 없다 |
| `usePbrTexture` | **1** | Albedo·ORM 채널을 함께 뽑는다. 1차 시도에서 쓸 만했던 설정 |
| `textureSize` | **2048** | 규격 상한과 일치 (4096은 낭비) |
| `topology` | `quad` | 나중에 손볼 여지를 남긴다. 그대로 쓸 거면 `tri` 도 무방 |
| `polygonCount` | **15,000** | 규격값. **올려도 형태가 좋아지지 않는다** |
| `useAlpha` | 입력에 배경이 없으면 1 | 배경이 섞이면 메시가 오염된다 |

> **`skipInputUpscale` 은 실재하는 파라미터입니다** (2026-09-16 정정).
> `get_node_catalog` 의 intrinsic 목록에는 없지만 노드 자체는 이 값을 가지고 있습니다.
> **카탈로그에 없다고 파라미터가 없는 것이 아닙니다** — 실제 노드 상태는
> `get_workflow_graph` 로 확인하십시오.

> **폴리곤 수는 형태 정확도가 아니라 표현 상한입니다.**
> `polygonCount` 를 30,000 → 100,000 으로 올려도 품질은 개선되지 않았습니다.
> 모델이 머리카락을 평면으로 이해하면, 폴리곤을 10 배 줘도 평면이 10 배 촘촘해질 뿐입니다.
> **폴리곤을 올려 해결하려 하지 마십시오.**

#### 2.2.0.1 노드별 크레딧 단가 (2026-09-16 · GAME_AI_CREATOR 등급)

**비용 구조가 전략을 결정합니다.**

| 노드 | 과금 액션 | 크레딧 |
|---|---|---|
| `GenerateImage` · `EditImage` | `GENERATE_IMAGE_V2` | **20** / 장 |
| `Generate3D` | `GENERATE_TEXTURED_MESH` | **200** / 개 |
| `Remesh` · `PBR` · `Rig` · `Animate` | — | **0** |
| `AIAssistant` | `GENERATE_TEXT` | 5 |
| `TextInput` · `ImageInput` | — | 0 |

> **3D 한 번이 이미지 열 장 값입니다.** 실패한 3D 생성 1회(200)면 이미지를 10장 뽑을 수 있습니다.
> 그러므로 **이미지를 넉넉히 뽑아 고른 뒤 3D 로 넘기는 것이 품질과 비용 양쪽에서 옳습니다.**
> 캐릭터 3종에 4장씩 = 240 크레딧으로, 3D 재생성 1회분(600)보다 쌉니다.
>
> `Rig` 와 `Remesh` 가 **0 크레딧**이라는 점도 기억하십시오 — 리깅 재시도는 공짜입니다.

#### 2.2.1 파츠 분할 생성 기준 — 전부 나누지 않는다

파츠를 따로 생성해 블렌더에서 병합하는 방식은 유효하지만, **무엇을 나눌지가 전부**입니다.
기준은 하나입니다 — **실물에서 분리 가능한 물건인가.**

| 구분 | 대상 | 생성 방식 |
|---|---|---|
| **몸체** (연속된 것) | 머리 · 목 · 몸통 · 팔 · 다리 · 몸에 붙는 의상 | **한 덩어리로 생성.** 나누면 접합부 이음새와 비율 정합 비용이 얻는 것을 넘는다 |
| **부착물** (분리 가능한 것) | 기즈모 건틀릿 · 로카 점퍼와 탄띠 · 스파크 관절 추진기와 고글 · 헤어 · RPG | **따로 생성해 병합.** UV 가 독립되어 텍스처 겹침이 구조적으로 사라진다 |

부착물 분할이 텍스처 문제를 푸는 이유는 이렇습니다 — 겹침은 **한 장의 텍스처에 여러 부위의
UV 가 몰려 있는데 메시 형태가 틀려서** 투영이 밀린 결과입니다. 부착물을 떼어내면
그 부위가 자기 UV 와 자기 텍스처를 갖게 되어 다른 부위를 침범할 수 없습니다.

반대로 **얼굴과 목을 따로 만들어 붙이면 접합선에서 노멀과 UV 가 끊깁니다.**
AI 출력은 매번 비율이 달라 수작업 정합 비용이 크고, 이음새는 카툰 렌더링에서 더 눈에 띕니다.

#### 2.2.1.1 3D 레벨 분할의 결정적 장벽 — 옷은 리깅을 따로 못 받는다

**(2026-09-16 확인. 이 절이 2.2.1 표보다 우선합니다.)**

상의·하의는 몸을 따라 굽으므로 **스킨드 메시**여야 합니다. 그런데 `Rig` 노드는
**완성된 전신 캐릭터**를 전제하므로 옷 조각만 넣으면 스켈레톤을 심지 못합니다.
스키닝 없는 옷을 Unity 에 넣으면 **캐릭터가 걸을 때 옷만 제자리에 남습니다.**

| 분리 가능 (강체 → 본에 부착) | 분리 불가 (스킨드 → 한 덩어리) |
|---|---|
| 헤어 · 고글/헬멧 · 건틀릿 · 무기 · 제트팩 | 몸 · 옷 · 얼굴 · 손 |

블렌더에서 스키닝을 직접 하면 뚫리지만, 리토폴로지보다 어려운 작업입니다.

#### 2.2.1.2 파츠별 3D 생성 후 블렌더 병합 (채택 — 2026-09-16)

**파츠마다 이미지를 따로 만들고, 3D 도 따로 뽑습니다. 병합은 블렌더에서 합니다.**

```
몸체 이미지(민머리·고글 없음) ─▶ Generate3D(tPose=1) ─▶ Rig   ← 스킨드, 리깅 대상
헤어 이미지                   ─▶ Generate3D(tPose=0)          ┐
고글 이미지                   ─▶ Generate3D(tPose=0)          ├ 강체 부착물
어깨 포드 이미지              ─▶ Generate3D(tPose=0)          │
무릎 포드 이미지              ─▶ Generate3D(tPose=0)          ┘
```

| 원칙 | 내용 |
|---|---|
| **몸체는 의상을 포함한다** | 옷은 스킨드 메시여야 하므로 몸에서 뗄 수 없습니다 (2.2.1.1). 몸체 = 옷 입은 전신 |
| **몸체는 민머리·맨얼굴로 뽑는다** | 헤어와 고글이 따로 오므로, 몸체에 있으면 겹칩니다. `COMPLETELY BALD`, `no goggles`, `face fully uncovered` |
| **붙을 자리를 비워 둔다** | `Shoulders and knees are smooth and bare with flat dark mounting plates ... no pods, no bulges` |
| **얼굴은 몸체에서 확정한다** | 고글이 없으므로 얼굴이 드러납니다. `Detailed face: large expressive eyes, clearly defined nose and lips` |
| **부착물은 한 종씩만 만든다** | 어깨 포드 1종을 좌우 복제, 무릎 포드 1종을 좌우 복제 |
| **부착물은 `tPose=0`** | 캐릭터가 아니므로 T 포즈 파라미터가 무의미합니다 |

##### 폴리곤 예산 — 현재 설정은 규격을 초과합니다

| 파츠 | `polygonCount` | 화면상 개수 | 합계 |
|---|---|---|---|
| 몸체 | 12,000 | 1 | 12,000 |
| 헤어 | 2,000 | 1 | 2,000 |
| 고글 | 1,200 | 1 | 1,200 |
| 어깨 포드 | 1,000 | 2 | 2,000 |
| 무릎 포드 | 1,000 | 2 | 2,000 |
| | | **합계** | **19,200** |

**규격은 15,000 tris 입니다** ([ADR-0007](../decisions/ADR-0007-캐릭터-에셋-반입-규격.md)).
`Generate3D` 의 `polygonCount` 최소값이 1,000 이라 부착물을 더 낮출 수 없는 것이 원인입니다.

> **대응: `Remesh` 노드가 0 크레딧입니다.** 포드처럼 단순한 덩어리는 200~300 tris 면
> 충분하므로, 생성 후 `Remesh` 로 깎으면 합계가 규격 안에 들어옵니다.
> (2차 시도에서 `Remesh` 가 문제였던 것은 **캐릭터 전신을 92% 깎았기** 때문이지,
> 노드 자체가 나쁜 것이 아닙니다. 단순 소품을 적당히 줄이는 용도로는 안전합니다.)

##### 병합 시 주의

- **스케일이 제각각으로 나옵니다.** 파츠마다 독립 생성이라 크기 기준이 없습니다.
  몸체를 먼저 임포트해 기준으로 삼고 나머지를 맞추십시오.
- **부착물은 블렌더에서 합치지 않아도 됩니다.** Unity 에서 해당 본
  (`Head` · `LeftShoulder` · `RightShoulder` · `LeftLowerLeg` · `RightLowerLeg`) 아래에
  자식 오브젝트로 넣으면 애니메이션을 따라갑니다. **블렌더 병합은 선택이지 필수가 아닙니다.**
- **머티리얼이 파츠 수만큼 늘어납니다.** 드로우콜이 캐릭터당 최대 5 로 증가합니다
  (ADR-0007 의 "1 슬롯"에서 벗어남). M2 프레임 측정 때 확인 항목입니다.

#### 2.2.2 파츠 분할이 새로 만드는 작업

채택하면 아래가 **전부** 따라옵니다. 비용을 알고 고르십시오.

| 항목 | 내용 |
|---|---|
| 리깅 | VARCO `Rig` 노드를 쓸 수 없다 (완성된 단일 메시를 전제하므로). 병합 후 **Mixamo 자동 리깅**으로 대체한다 — T 포즈 단일 메시를 올리면 Humanoid 호환 본을 붙여주므로 [ADR-0007](../decisions/ADR-0007-캐릭터-에셋-반입-규격.md) 요건은 충족된다 |
| 머티리얼 | 파츠 수만큼 슬롯이 늘어 **"캐릭터당 1 슬롯" 규격을 위반한다.** 블렌더에서 UV 재패킹 + 텍스처 베이크로 한 장에 통합해야 한다. **이 단계가 파츠 분할 비용의 대부분이다** |
| 스케일 정합 | 부착물을 몸체 비율에 맞춰 수동 정렬한다. AI 출력은 매번 크기가 다르다 |
| 폴리곤 | 파츠 합계가 15,000 tris 를 넘지 않는지 **병합 후** 확인한다 |
| 생성 비용 | 캐릭터당 생성 횟수가 파츠 수만큼 늘어난다 |

#### 2.2.3 3D 친화 디자인 규칙 — 입력을 고치는 쪽이 싸다

파츠 분할보다 **먼저** 손댈 곳은 입력 이미지입니다. 생성 모델이 못 만드는 형태를
애초에 요구하지 않으면 비용 없이 품질이 올라갑니다.

| 규칙 | 이유 |
|---|---|
| **얇고 긴 돌출을 만들지 않는다** | 머리카락 가닥 · 늘어진 끈 · 얇은 날개는 단일 이미지에서 복원 불가. 뭉개진다 |
| **머리카락은 덩어리로 묶는다** | **[D-028 결정 — 헬멧으로 덮지 않는다]** 머리카락은 유지하되, 흩날리는 결·긴 포니테일 대신 **짧고 굵은 포니테일이나 번(쪽)머리**처럼 하나의 덩어리로 설계한다 |
| **T 포즈로 그린다** | 팔을 좌우로 벌린 자세로 생성해야 겨드랑이가 붙지 않는다. `tPose` 파라미터와 짝을 이룬다 (2.2.0) |
| **덩어리 실루엣으로 설계한다** | 큰 면과 각진 형태는 잘 나온다. [ADR-0006](../decisions/ADR-0006-캐릭터-실루엣-불변.md)의 실루엣 구분 요구와 같은 방향이다 |
| **부위 간 명도를 벌린다** | 인접 부위의 명도가 비슷하면 투영 단계에서 경계를 못 찾아 텍스처가 번진다 |

> **이 게임의 교전 거리는 20~40 m 이고 렌더링은 카툰입니다** (gdd 16장).
> 머리카락 가닥과 얼굴 디테일은 **플레이 중 보이지 않습니다.**
> ADR-0006 이 이미 "색이 아니라 형태로 구분한다"고 못박았으므로,
> 디테일이 아니라 **실루엣에 투자하는 것이 이 프로젝트에 맞습니다.**

#### 2.2.4 시도 순서 (비용 오름차순)

위에서부터 시도하고, 통과하면 아래로 내려가지 마십시오.

1. **노드 파라미터 교정** (2.2.0) — 특히 **`tPose` = 1**. 설정만 바꾸면 되므로 가장 쌉니다
2. **`Remesh` · `Texture3D` 제거** → `Generate3D(15,000, 텍스처 포함) → Rig`
   1차 시도에서 로카·기즈모가 쓸 만했던 구성이고 규격(15,000)과도 일치합니다
3. **이미지 단계에서 걸러낸다** — `GenerateImage` 의 `count` 를 올려 여러 장 뽑고
   2.2.3 규칙에 맞는 것만 3D 로 넘깁니다. **이미지는 ~40초, 3D 는 ~4분입니다.
   싼 단계에서 거르는 것이 이 워크플로우에서 가장 효율이 높은 개입 지점입니다**
4. **`EditImage` 로 입력 이미지를 고친다** — 블렌더 대신 이미지 단계에서 수정합니다
5. **부착물만 파츠 분할 + 블렌더 병합** (2.2.1 · 2.2.2)
6. 위로 안 되면 수작업 모델링 — 이 프로젝트의 AI 활용 목표와 어긋나므로 최후 수단

> **블렌더 수작업(리토폴로지 · 텍스처 페인팅)은 5단계 이후입니다.** 작업자가
> 블렌더 미숙련이라면(2026-09-16 확인) 1~4 를 전부 소진하기 전에 내려가지 마십시오.
> 리토폴로지는 블렌더에서 가장 숙련이 필요한 작업이고, **UV 가 어긋난 상태에서
> 텍스처를 덧그리면 엉뚱한 곳에 칠해집니다** — 먼저 UV 를 고쳐야 하는데 그쪽이 더 어렵습니다.
>
> **텍스처가 끝내 안 나오면 그리지 말고 버리십시오.** 교전 거리 20~40 m 에 카툰
> 렌더링이므로(gdd 16장), Unity 에서 URP Lit 의 Base Color 를 단색으로 주고
> 머티리얼을 2 슬롯(몸 / 장비)으로 나누는 편이 망가진 텍스처보다 낫습니다.
> 이 경로는 블렌더가 전혀 필요 없습니다.

#### 2.2.5 현재 워크플로우 구성 (2026-09-16 재구축)

VARCO 커스텀 워크플로우 `57a283e3-5b02-49e4-b500-f6276848cab7`.
캐릭터 3종이 각각 아래 한 줄을 갖습니다 (총 15 노드).

```
[탐색]  TextInput ──▶ GenerateImage (count=4)      ← 먼저 여기만 실행한다
[생산]  ImageInput ──▶ Generate3D ──▶ Rig          ← 고른 이미지를 꽂고 실행한다
```

**두 구간을 일부러 끊어 두었습니다.** `GenerateImage` 출력을 `Generate3D` 에 직결하면
4장이 전부 3D 로 넘어가 800 크레딧이 나갑니다. 사람이 고른 한 장만
`ImageInput` 에 넣어 200 크레딧으로 막습니다.

`Remesh` 와 `Texture3D` 는 **넣지 않았습니다** — 2차 시도에서 메시를 뭉갠 원인이고,
`Generate3D` 의 `generateTexture` 가 텍스처까지 처리하므로 존재 이유가 없습니다.

**`Art/` 에는 원본 아트 에셋만** 둡니다. 조립된 프리팹은 `Assets/_Project/Prefabs/` 입니다.

      SK_Spark.fbx
      Materials/     M_Spark.mat
      Textures/      T_Spark_Albedo · T_Spark_Normal · T_Spark_MetallicSmoothness · T_Spark_AO
    Rocca/           같은 구성

    SkyYard/

      Materials/
      Textures/
  Weapons/
    Rpg/             SK_Rpg.fbx (캐릭터 손에 붙으므로 스킨드)
    Rocket/          SM_Rocket.fbx
  VFX/
    Materials/       M_Explosion.mat ...

    Skills/          대시 · 예비탄 · 갈고리

**캐릭터는 대상별로 묶고, 애니메이션은 밖에 둡니다.**
캐릭터 폴더를 묶는 이유는 스킨(코스메틱)이 추가될 때 그 캐릭터 아래로 확장되기 때문이고,
애니메이션을 빼는 이유는 Humanoid 리깅 덕분에 **세 캐릭터가 같은 클립을 공유**하기 때문입니다.
특정 캐릭터 폴더에 넣으면 소속이 틀립니다.

> 캐릭터 FBX는 스킨드 메시이므로 **`SK_` 접두**를 씁니다 (3장 명명 규칙).
> VARCO 3D 출력 파일명(`Rocca.fbx`)을 그대로 두지 말고 `SK_Rocca.fbx` 로 바꾸십시오.

## 3. 명명 규칙 (확정)

| 종류 | 규칙 | 예 |
|---|---|---|
| 모델 | `SM_<대상>` / 스킨드는 `SK_<대상>` | `SK_Rocca` |
| 머티리얼 | `M_<대상>` | `M_Rocca` |
| 텍스처 | `T_<대상>_<채널>` | `T_Rocca_Albedo` |
| 프리팹 | `P_<대상>` | `P_Rocket` |
| VFX | `VFX_<사건>` | `VFX_Explosion` |
| 오디오 | `SFX_<사건>` / `BGM_<곡명>` | `SFX_RocketLaunch` |
| 데이터 (ScriptableObject) | `SO_<대상>` | `SO_CombatConfig` |

대소문자와 구분자는 위 형식 그대로. 공백과 한글 파일명은 쓰지 않습니다.
(Unity 에셋 경로에 한글이 섞이면 일부 도구 체인에서 문제가 생깁니다)

## 4. 캐릭터 반입 절차

순서대로 진행하고, 각 단계를 통과하지 못하면 **다음으로 넘어가지 말고 모델을 고치십시오.**

### 4.1 생성

VARCO 3D로 생성합니다. 프롬프트는 [worldbuilding.md](../design/worldbuilding.md) 3장의
외형 묘사와 1장 컬러 테마를 기초로 씁니다.

### 4.2 배치

`Assets/_Project/Art/Characters/<캐릭터명>/` 에 `SK_<캐릭터명>.fbx` 로 넣습니다 (2.3절 구조).

### 4.3 규격 검수

Project 창에서 FBX를 선택하면 **Inspector 맨 아래 프리뷰 영역**에 `verts / tris` 가 표시됩니다.

- [ ] 삼각형 15,000 이하
- [ ] 단위 1 unit = 1 m — 캐릭터 키가 약 1.8 m로 들어오는가
- [ ] 피벗이 발밑 (0,0,0)
- [ ] 정면이 +Z
- [ ] 머티리얼 슬롯 1개 (최대 2개)
- [ ] 텍스처 2048 이하, Albedo·Normal 존재

### 4.4 임포트 설정

| 탭 | 항목 | 값 |
|---|---|---|
| Model | Scale Factor | 1 |
| Model | Convert Units | 체크 |
| Model | Mesh Compression | Medium |
| Model | Read/Write | **해제** (런타임 메시 수정이 없다. 메모리 절감) |
| Model | Optimize Mesh | 체크 |
| Rig | Animation Type | **Humanoid** |
| Rig | Avatar Definition | Create From This Model |
| Animation | Import Animation | **해제** (애니메이션은 별도 관리) |
| Materials | Material Creation Mode | Standard |

### 4.5 리깅 확인

- [ ] Rig 탭에서 Humanoid로 설정하고 Apply 했는가
- [ ] **Configure** 를 열어 필수 본이 모두 매핑되는가 (빨간 표시가 없어야 함)
- [ ] 본 구조가 좌우 대칭인가 — 기즈모의 건틀릿은 **메시**여야 하고 본이 아니다
- [ ] T-pose 또는 A-pose로 들어오는가

매핑이 실패하면 Configure에서 수동으로 맞추거나, 후처리(자동 리깅)를 거칩니다.

### 4.6 텍스처와 머티리얼

**FBX에서 추출하지 말고 원본 텍스처 폴더에서 복사합니다** (2.1.2절).

- [ ] 텍스처 4장을 `Textures/` 에 `T_<캐릭터>_<채널>` 이름으로 복사한다 (ORM은 제외)
- [ ] Unity에서 `Ctrl+R` 로 새로고침한다
- [ ] `T_<캐릭터>_Normal` 을 선택하고 **Inspector 맨 위 Texture Type 을 `Normal map`** 으로
      바꾼 뒤 Apply — 이 설정은 PNG를 선택했을 때만 보이며 FBX에는 없다
- [ ] `Materials/` 에서 우클릭 → `Create > Material` → `M_<캐릭터>` 생성
- [ ] Shader를 `Universal Render Pipeline/Lit` 으로 두고 아래를 연결한다

| URP Lit 슬롯 | 텍스처 |
|---|---|
| Base Map | `T_<캐릭터>_Albedo` |
| Normal Map | `T_<캐릭터>_Normal` |
| Metallic Map | `T_<캐릭터>_MetallicSmoothness` |
| Occlusion Map | `T_<캐릭터>_AO` |

- [ ] 씬의 캐릭터 또는 프리팹의 Mesh Renderer Material 슬롯에 `M_<캐릭터>` 를 지정한다

### 4.7 실루엣 테스트

색을 빼고 형태만으로 세 캐릭터가 구분되는지 확인합니다. **색으로 보완하지 마십시오.**

- [ ] 세 캐릭터를 단색(검정)으로 렌더한다
- [ ] 정면 · 측면 · 후면 세 각도에서 비교한다
- [ ] 색 정보 없이 어느 캐릭터인지 **즉시** 구분된다
- [ ] 30 m 거리(교전 거리 하한)에서 보이는 크기로 축소해도 구분된다

카운터 삼각관계(gdd 5.2)는 상대 클래스를 즉시 알아야 성립하므로,
이 테스트는 게임플레이 요구사항이지 아트 취향의 문제가 아닙니다.
**세 캐릭터가 모두 반입된 뒤에 한 번에 수행합니다.**

### 4.8 프리팹화

`Assets/_Project/Prefabs/` 에 `P_<캐릭터명>` 으로 저장합니다 (예: `P_Rocca`).
